# 手すき時間のサムネ生成

表示中のフォルダで、画面外（先読みの窓の外）のサムネ未生成のファイルを、操作が止まっている間だけ自動で生成してDBキャッシュに貯める。
通常のサムネ生成は、表示範囲とスクロール方向に1画面分だけ先読みする遅延方式のため、画面外のファイルは初めてスクロールした時に
生成が始まる。手すきの間に先回りしておくと、そのスクロールの待ちが減る。

## 動作

| 項目 | 内容 |
|---|---|
| 開始条件 | エクスプローラー窓で、最後の「操作」から設定の待ち時間（既定1秒、1〜30秒）以上たったとき。「操作」はキー・テキスト入力・コピー貼り付け・**クリック（動かさずに押して離す）**だけで、**マウスの移動・ホイールでの一覧のスクロール・ドラッグ（スクロールバー・範囲選択・タッチのスワイプ）・フォーカス変化は数えない** |
| 同時に満たす条件 | 通常のサムネ処理（先読みキュー・保留）が空 / 設定がON / ビューアー窓が閉じている（設定の「開いている間も続ける」がOFFのときだけ。既定はON＝開いていても続ける）/ 計測フィクスチャーが動いていない |
| 対象 | 表示中の実フォルダ（実ツリー・仮想フォルダのタブ。仮想ノードは実パスのフォルダ）直下のファイルのうち、**現設定のサムネとして作り直す必要があるもの**（`thumb_needs_generation`）。未生成（`Missing`）に加えて、設定変更後の旧形式（`Stale`・別のサイズ/フィルタで完成した `Current`）を含む。生成中（`Processing`）は除く。ID解決済みのものだけ。ネットワークパス（gvfs）は除く。お気に入り・検索・類似・タグ検索の飛び地一覧は対象外 |
| 画面表示用のディスク読みとの兼ね合い | ページ読み・アーカイブ展開などが動いている間と、その終了から1.5秒は、新規送信を止める（止めるのは新規だけ。読み終わり・手が止まれば自動で再開）。[archive-open-perf.md](archive-open-perf.md) §4.2 |
| 同時実行数 | 1件固定（外付けHDDでは並列にしても速くならず、操作再開時の影響だけが増えるため） |
| 操作があったら | 新規の送信を止める（マウスを動かす・スクロールする・ドラッグ／スワイプするだけでは止まらず、続きから進む）。送信済みの分は完走させる。次の手すきで一覧の先頭から見直す（生成済みはDBの状態で飛ばす） |
| 結果の扱い | DBに保存するだけ（テクスチャにはしない）。画面に出るときにDBから読む |
| 更新の契機 | 手すき生成の1件ごとには、dHash・サマリーの更新を走らせない（手すき生成の保留は「保留が空になった」判定から外す）。周が終わった時に、生成したものがあれば1回だけ走る |
| 表示 | UIには出さない |

- 「検証中」（ID解決待ち）のファイルは飛ばし、周の終わりに1秒おきで見直す（サムネの引っ越しの前提を崩さないため）
- 1フレームに確認する件数は16件までで、UIを重くしない
## 設定

トップレベルのUI（メニュー・ツールバー）には出さない。既定の動作として常時有効で、変更は設定画面だけで行う。

設定→**共通**タブ、サムネのリサイズフィルタの直後（「隠しファイルを表示」の前）。

| 項目 | 既定 | state キー | 備考 |
|---|---|---|---|
| 操作が止まっている間に、現在地フォルダのサムネ生成を続ける | ON | `app_idle_thumb_generation` | OFFのとき、下の2項目はグレーアウト |
| 最後の操作から始めるまでの待ち時間 | 1秒（1〜30。サムネが未完成の時間を短くするため、既定を3秒から1秒にした。保存済みの値はそのまま） | `app_idle_thumb_wait_secs` | 範囲外は読み込み時と反映時に丸める |
| ビューアーを開いている間も続ける | ON | `app_idle_thumb_while_viewer` | ONだと、本のページ読み込みとディスクを取り合うことがある。OFFにすると、ビューアーが開いている間は止まる |

文言は日本語・英語・中国語（`i18n.rs` の `settings_idle_thumb_*`）。設定は、ダイアログの「反映」で `AppConfig` に入り、次のフレームから効く。

## ログ（確認用）

設定→デバッグの「サムネ周りのリファクタリング用ログ」がONの間だけ、標準出力へ出す。送信が1件も無かった周は出さない。

```
[idle-thumb] 開始: /path/to/dir（一覧 168 件、同時 1 件まで）
[idle-thumb] 送信 100 件（+8.2s）
[idle-thumb] 入力で中断: 送信 120 件（+10.1s）     # 操作が再開した時
[idle-thumb] 周が完了: 送信 168 件（+14.6s）
```

## 計測フィクスチャーで確認する手順

1. 上のログ設定をONにする
2. カード右クリックの「…クリアし計測を開始する」を選び、確認ダイアログで **「画面外も含めて全件のサムネを生成して測る」を外す**
   （ONのままだと全件が計測の中で生成され、手すき生成の出番が残らない）
3. 集計が出て計測が終わるまで待つ（計測中は手すき生成が止まる）
4. 集計の後、1秒以上キー・クリックをしない（マウスを動かしていてもよい）。`[idle-thumb] 開始` が出て、画面外の分が生成される
5. 途中でキーを押す・クリックすると `入力で中断` が出る。止めた後、また1秒待つと再開する。マウスを動かす・ホイールでスクロールする・スクロールバーをドラッグする・タッチでスワイプするだけでは中断しない

## 実装

- `src/view_explorer/idle_thumb.rs` — 進行状態と `pump_idle_thumbnails`（`poll_workers` から毎フレーム、通常のサムネ処理の後に呼ぶ）
- 最後の操作は、手すき専用の `idle_last_activity`（`OperationTracker` が「操作」と見分けたイベントのあるフレームで更新。許可リスト方式）を使う。
  クリックは、離したときに、押した位置から 6pt 以内なら数える（押した瞬間は数えない。ドラッグは動いたら数えない）。`Touch` イベントは数えず、タップは egui-winit が翻訳する `PointerButton` の押下と離すで、クリックとして数える。
  サムネ生成の並列度の絞り（操作の直後は2並列）は、従来どおり `thumb_last_user_activity`（あらゆるイベントで更新）を使い、別のタイマー。
  ビューアー窓の入力は含まない

## 手動確認項目

1. 大きなフォルダ（数百件）を開き、キー・クリックをせずに（マウスを動かしていてもよい。ホイール・スクロールバーのドラッグ・タッチのスワイプも可）1秒以上待つ。端末の `top` 等で、ディスクとCPUが動き始めること
2. その後、フォルダの末尾へスクロールして、サムネがすでに出ていること（初回より速い）
3. 手すき生成の最中にマウスを動かすと、新規の送信が止まり、操作が重くならないこと
4. ビューアーを開いている間の動作が、設定（既定ON＝続ける）に従うこと。続ける場合に、本のページ送りが重くならないか
5. 別のフォルダへ移動したとき、前のフォルダの手すき生成が引き継がれないこと
6. 設定→共通で、チェックを外すと手すき生成が止まり、グレーアウトされること。再びONにすると再開すること
7. 待ち時間を10秒にして、最後の操作から10秒後に開始すること（ログON時は `開始` の出る時刻で確認）
8. 既定（ON）で、ビューアーを開いたままでも `送信` が進むこと。OFFにすると、ビューアーが開いている間は止まること
9. 設定を変えてアプリを再起動しても、3項目が保持されること

## 設定変更後の旧サムネの更新（サムネサイズ・フィルタ）

サムネサイズ・リサイズフィルタを変えると、貯めたサムネは旧形式になり、メニューバーに「新形式に更新中」が出る。
以前は、画面に入ったセルと先読みの窓だけが更新され、画面外と、すでにテクスチャを持つセルは、スクロールやフォルダへの入り直しまで進まなかった。今は自動で進む。

- 設定変更を検出した時点（`refresh_thumbnail_generation_state`）で、表示中のテクスチャのパスを `thumb_stale_textures` に控える。**旧サムネは見せたまま**、新形式が届いたら差し替える（灰色に戻さない）
- 画面に見えているセルは、旧テクスチャでも直接リクエストする（`request_visible_thumbnail`。生成中・失敗済み・先読み待ち・ID解決待ちは出さない）。先読みの窓でも、旧テクスチャは「表示済み」とみなさない
- 画面外は手すき生成が、一覧の先頭から順に作り直す（同時1件）。設定変更時に、終わっていても最初から見直す（`force_restart`）
- 新形式（`Complete`）が届くと、旧形式の印を外す（旧画像のプレビューでは外さない）。フォルダに入り直してテクスチャを空にしたときも消える
- 対象は表示中のフォルダだけ。ほかのフォルダの旧サムネは、そのフォルダを開いたときに更新される
- 判定は `neko_dir::thumbnail_needs_regeneration`（状態と生成条件だけを見る。元ファイルの更新日時との突合は、生成開始時の `claim_thumbnail_generation` が行う）

### 手動確認項目（設定変更後の更新）

1. サムネが貯まったフォルダで、サムネサイズを変更して反映する。画面内のサムネが、灰色に戻らず、順に新サイズへ差し替わる
2. 操作せず（マウスを動かすだけでよい）に放置する。画面外のサムネも順に更新され、メニューバーの「新形式に更新中」が消える
3. 仮想フォルダのタブでも、同じ手順で更新される
4. 更新の途中でキー・クリックをすると、手すき生成は中断し、1秒後に再開する
5. 更新が終わったあと、もう一度同じサイズに戻す設定変更でも、同様に更新される
