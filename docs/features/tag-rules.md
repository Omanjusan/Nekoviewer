# タグ自動取得の大ルール（穴埋め式スクリプト）

「現フォルダ内タグ情報取得」の前処理。ファイルごとに条件を判定し、成立したルールが無効にした種類の言及を、未採用・要確認で残す。
例: `AI generated` を含むファイルは、作者・グループ・イベントを無効にする。

> 状態: R1（ルールの型・保存・評価）、R2（抽出への接続・理由表示）、R3（新種類と cosplay の文法）まで実装済み。**ルールの編集UI（R4）は未実装**。
> それまでは、設定フォルダの `nekoviewer_tag_rules.json` を手で置く（下の「実機確認」を参照）。
> ComicInfo.xml / meta.json の取得（X）も未実装。

## ルールの構造（`src/tag_rules.rs`）
- **条件**（1ルールに複数。「どれか」または「すべて」で成立）
  - 文字列: 対象 × 照合 × 文字列。対象は、ファイル名（拡張子を除く）／info.txt の見出し行（複数行ならどの行でも）／info.txt の Category／題名（括弧 `(...)` `[...]` を除いた部分）。照合は、文字列内一致・前方一致・完全一致
  - ファイル名の形: `X - Y`／`X - Y (Z)`／`X - Y - Z`。区切りは前後に半角スペースのある ` - ` だけ（`Honkai-Star Rail` のハイフンは区切りにしない）。括弧で始まる名前は対象外
  - 文字列の照合は、既存の完全一致キー（全角半角・空白・ハイフン・アンダーバー・記号・大小を同一視）。`AI Generated` / `ai-generated` / `ＡＩ　ｇｅｎｅｒａｔｅｄ` は同じ扱い
- **効果**: 無効にする種類／有効にする種類。種類は、形式・メイン・言語・イベント・作者・グループ（既存6つ）と、演者・キャラ・パロディ元（新種類。ルールで有効にしたときだけ取る）、属性・年月（新種類。ComicInfo.xml・meta.json があるときに取る。無効にはできる）。同じ種類を無効と有効の両方にはできない
- **競合**: 成立したルールをすべて適用する。無効は和集合。有効にする種類は、無効の側に入っていないものだけが残る。新種類は、有効にしたルールがあるときだけ取る
- **プリセット**（7種）: AI generated／cosplay／画集・イラスト集／3D・CG集／doujinshi／manga／anthology
  - 効果の既定があるもの: AI generated（作者・グループ・イベントを無効、パロディ元を有効）／cosplay（作者・グループ・イベントを無効、演者・キャラ・パロディ元を有効）／anthology（作者・グループを無効）。他は条件だけで、効果はユーザーが選ぶ
  - doujinshi・manga は info.txt の Category だけを見る
- **保存**: 設定フォルダの `nekoviewer_tag_rules.json`（tmp→rename）。ルールは順序つき。削除したIDは再利用しない

## 抽出への接続（R2）
- 候補生成（`build_candidates_full`）の「言及を集める」段階のあとで、ファイルごとにルールを評価する
- 無効にされた種類の言及は、候補から消さず、**未採用・要確認**で残す。初期の扱いは「付けない」
- **ルールは既存マスタの完全一致より優先**する（ルールが無効にしたら、マスタに同じタグがあっても未採用）。学習モデルの「無視」判定は、従来どおりマスタ優先
- 同じ名前を、ルールの影響を受けないファイルも持っているときは、そちらがあるので採用のまま（ファイルごとに判定し、候補は全ファイルの言及をまとめたもの）
- 形式・メイン・言語のようなシステム系も、ルールで無効にできる
- 学習モデルを使う経路でも、同じようにルールを適用する
- 確認ウィンドウ
  - 上部に「大ルール適用: AI generated 3件 / …」
  - 候補行に「要確認: ルール「AI generated、anthology」で無効」（学習による無視は「要確認: 学習で無視と判定」）
  - 「未確定のみ表示」には、要確認の候補も含める
- ルールは取得ボタンを押した時点の内容で適用する（確認ウィンドウの作り直しでも同じルール）

## 新種類と cosplay の文法（R3）
- 新種類: **演者**（窓2）・**キャラ**・**パロディ元**（窓1）。抽出が既定では取らない種類で、**ルールが「有効にする」と指定したとき、そのファイルでだけ**取る。ルールで無効にもできる
- 取得元: ` - ` 区切りの題名。info.txt の見出し（内部照合の行）が ` - ` 区切りならそれ、でなければファイル名
  - `演者 - キャラ (パロディ元)`（例: `Tiny Asa アサ - Castorice (Honkai-Star Rail).zip`）
  - `演者 - キャラ - パロディ元`（例: info.txt の `希尔薇 - w旗袍 - Arknights`）
  - `演者 - キャラ`（最小単位。パロディ元は任意）
  - 区切りは前後に半角スペースのある ` - ` だけ。括弧で始まる題名は対象外
- info.txt の別の見出し行が同じ形なら、同じ位置の名前を対にして別名として登録する（`カストリス|Castorice`）
- 既存のカテゴリは、名前（演者／キャラクター／パロディ元 など）で探し、無ければ適用時に新規作成する。既存要素と完全一致すれば既存に付ける。キャラ・パロディ元は類似候補も出す
- 確認ウィンドウの種類の見出し: 「演者」「キャラ」「パロディ元」。窓2のタイトルは今のまま「作者・グループ」系の表記（演者も窓2に並ぶ）
- cosplay を info.txt が無いファイルでも拾うには、「ファイル名の形」の条件が必要（編集UI R4 で選べるようにする。今は下の書き出しに含めた）。` - ` を含む通常の題名（`Title - Sub (x)`）に誤って当たる可能性があるため、フォルダを選んで使う

## 仮の入口（編集UIができるまで）
- タグパネルの学習行の下に、`大ルール…` ボタンとルールの件数（`ルール 3件` / `ルール無し`）。ボタンで一覧窓を開閉する（配置は仮。編集UIの置き場所は後で決める）
- 一覧窓は読み取り専用。ルール名（無効のルールは薄く `（無効）`）と、概要（`条件 N件（いずれか/すべて） / 無効: … / 有効: …`）を出す
- `再読込` で、設定フォルダの `nekoviewer_tag_rules.json` を読み直す（ファイルが無ければ、ルールを空にする。壊れている・新しい版のときは、いまのルールを残してトーストで知らせる）。アプリの再起動は不要
- 窓が開いている間は、エクスプローラーのキー操作を止める

## 実機確認（編集UIができるまで）
- 効果の既定があるプリセット3つと、cosplay のファイル名の形のルールを、設定フォルダに書き出す
  `NEKO_RULES_OUT=<設定フォルダ> cargo test export_default_preset_rules -- --ignored --nocapture`（既存のルールは上書き）
- アプリを再起動し、`現フォルダ内タグ情報取得` を押す

## 手動テスト（R2）
1. ルール無し（`nekoviewer_tag_rules.json` が無い）で取得すると、従来と同じ結果になる
2. 上のコマンドでルールを書き出して再起動。ファイル名に `[AI Generated]` を含むアーカイブ（例: `[Circle (Author)] Book [AI Generated].zip`）を含むフォルダで取得する
3. 確認ウィンドウ上部に「大ルール適用: AI generated 1件」が出る
4. そのファイルの作者・グループ・イベントが未採用で、「要確認: ルール「AI generated」で無効」と出る。形式（zip）と言語は採用のまま
5. 同じ作者名を持つ、ルールに当たらないファイルがあれば、その作者は採用のまま
6. info.txt の `Category: Cosplay` を持つアーカイブでは、作者・グループ・イベントが「要確認: ルール「cosplay」で無効」になる
7. 題名に `Anthology` / `アンソロジー` を含むと、作者・グループが「要確認: ルール「anthology」で無効」になる
8. 「すべて採用」を押すと、要確認の候補も採用される（確認の上で使う）
9. 「未確定のみ表示」にチェックすると、要確認の候補も出る
10. マスタに同じ作者名のタグがあっても、ルールが当たったファイルでは未採用のまま
11. しきい値スライダーなどで確認ウィンドウを作り直しても、同じルールが適用される
12. アプリを再起動しても、ルールが保たれる

## 手動テスト（R3）
1. 上のコマンドでルールを書き出して再起動する
2. `Tiny Asa アサ - Castorice (Honkai-Star Rail).zip` のようなファイルがあるフォルダで取得 → 窓2に「演者」の `Tiny Asa アサ`、窓1に「キャラ」の `Castorice`、「パロディ元」の `Honkai-Star Rail` が出て、初期採用になる（`cosplay（ファイル名の形）` が成立）
3. info.txt が `Category: Cosplay` で、見出しが `希尔薇 - w旗袍 - Arknights` のアーカイブ → 演者 `希尔薇`、キャラ `w旗袍`、パロディ元 `Arknights`。作者・グループ・イベントは要確認（ルール「cosplay」で無効）。形式・言語は採用のまま
4. 見出しが `演者 - キャラ`（2つだけ）のときは、パロディ元の候補が出ない
5. 見出しが ` - ` 区切りでない cosplay（Category だけ Cosplay）は、新種類を取らない
6. 英語行・日本語行の2行で同じ形なら、`カストリス|Castorice` のように別名つきで登録される
7. マスタに「演者」「キャラクター」「パロディ元」のカテゴリがあれば、そこに照合・追加される。無ければ、適用時にカテゴリが作られる
8. 通常の同人誌（`[サークル (作者)] 題名`）は、これまでと同じ結果のまま
