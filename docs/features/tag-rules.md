# タグ自動取得の大ルール（穴埋め式スクリプト）

「現フォルダ内タグ情報取得」の前処理。ファイルごとに条件を判定し、成立したルールが無効にした種類の言及を、未採用・要確認で残す。
例: `AI generated` を含むファイルは、作者・グループ・イベントを無効にする。

> 状態: R1（ルールの型・保存・評価）、R2（抽出への接続・理由表示）、R3（新種類と cosplay の文法）まで実装済み。**ルールの編集UI（R4）は未実装**。
> それまでは、設定フォルダの `nekoviewer_tag_rules.json` を手で置く（下の「実機確認」を参照）。
> ComicInfo.xml / meta.json の取得（X）も未実装。

## ルールの構造（`src/tag_rules.rs`）
- **条件**（1ルールに複数。「どれか」または「すべて」で成立）
  - 文字列: 対象 × 照合 × 文字列。対象は、ファイル名（拡張子を除く）／info.txt の見出し行（複数行ならどの行でも）／info.txt の Category／題名（括弧 `(...)` `[...]` を除いた部分）。照合は、文字列内一致・前方一致・完全一致
  - ファイル名の形: `X - Y`／`X - Y (Z)`／`X - Y - Z`。区切りは前後に半角スペースのある ` - ` だけ（`Honkai-Star Rail` のハイフンは区切りにしない）。括弧で始まる名前は対象外
  - 文字列の照合は、既存の完全一致キー（全角半角・空白・ハイフン・アンダーバー・記号・大小を同一視）。`AI Generated` / `ai-generated` / `ＡＩ　ｇｅｎｅｒａｔｅｄ` は同じ扱い
- **効果**: 無効にする種類／有効にする種類。種類は、形式・メイン・言語・イベント・作者・グループ（既存6つ）と、演者・キャラ・パロディ元（新種類。ルールで有効にしたときだけ取る）、属性・年月（新種類。ComicInfo.xml・meta.json があるときに取る。無効にはできる）。同じ種類を無効と有効の両方にはできない
- **競合**: 成立したルールをすべて適用する。無効は和集合。有効にする種類は、無効の側に入っていないものだけが残る。新種類は、有効にしたルールがあるときだけ取る
- **プリセット**（7種）: AI generated／cosplay／画集・イラスト集／3D・CG集／doujinshi／manga／anthology
  - 効果の既定があるもの: AI generated（作者・グループ・イベントを無効、パロディ元を有効）／cosplay（作者・グループ・イベントを無効、演者・キャラ・パロディ元を有効）／anthology（作者・グループを無効）。他は条件だけで、効果はユーザーが選ぶ
  - doujinshi・manga は info.txt の Category だけを見る
- **保存**: 設定フォルダの `nekoviewer_tag_rules.json`（tmp→rename）。ルールは順序つき。削除したIDは再利用しない

## 抽出への接続（R2）
- 候補生成（`build_candidates_full`）の「言及を集める」段階のあとで、ファイルごとにルールを評価する
- 無効にされた種類の言及は、候補から消さず、**未採用・要確認**で残す。初期の扱いは「付けない」
- **ルールは既存マスタの完全一致より優先**する（ルールが無効にしたら、マスタに同じタグがあっても未採用）。学習モデルの「無視」判定は、従来どおりマスタ優先
- 同じ名前を、ルールの影響を受けないファイルも持っているときは、そちらがあるので採用のまま（ファイルごとに判定し、候補は全ファイルの言及をまとめたもの）
- 形式・メイン・言語のようなシステム系も、ルールで無効にできる
- 学習モデルを使う経路でも、同じようにルールを適用する
- 確認ウィンドウ
  - 上部に「大ルール適用: AI generated 3件 / …」
  - 候補行に「要確認: ルール「AI generated、anthology」で無効」（学習による無視は「要確認: 学習で無視と判定」）
  - 「未確定のみ表示」には、要確認の候補も含める
- ルールは取得ボタンを押した時点の内容で適用する（確認ウィンドウの作り直しでも同じルール）

## 新種類と cosplay の文法（R3）
- 新種類: **演者**（窓2）・**キャラ**・**パロディ元**（窓1）。抽出が既定では取らない種類で、**ルールが「有効にする」と指定したとき、そのファイルでだけ**取る。ルールで無効にもできる
- 取得元: ` - ` 区切りの題名。info.txt の見出し（内部照合の行）が ` - ` 区切りならそれ、でなければファイル名
  - `演者 - キャラ (パロディ元)`（例: `Tiny Asa アサ - Castorice (Honkai-Star Rail).zip`）
  - `演者 - キャラ - パロディ元`（例: info.txt の `希尔薇 - w旗袍 - Arknights`）
  - `演者 - キャラ`（最小単位。パロディ元は任意）
  - 区切りは前後に半角スペースのある ` - ` だけ。括弧で始まる題名は対象外
- info.txt の別の見出し行が同じ形なら、同じ位置の名前を対にして別名として登録する（`カストリス|Castorice`）
- 既存のカテゴリは、名前（演者／キャラクター／パロディ元 など）で探し、無ければ適用時に新規作成する。既存要素と完全一致すれば既存に付ける。キャラ・パロディ元は類似候補も出す
- 確認ウィンドウの種類の見出し: 「演者」「キャラ」「パロディ元」。窓2のタイトルは今のまま「作者・グループ」系の表記（演者も窓2に並ぶ）
- cosplay を info.txt が無いファイルでも拾うには、「ファイル名の形」の条件が必要（編集UI R4 で選べるようにする。今は下の書き出しに含めた）。` - ` を含む通常の題名（`Title - Sub (x)`）に誤って当たる可能性があるため、フォルダを選んで使う

## ルール一覧窓（R4-a・P4）
- 入口: タグパネル最上段の `🏷 タグ管理` メニューの `タグ抽出ルール定義開始`（右に件数 `有効 N件 / 全M件` / `ルール無し`）。押すと、窓「タグ抽出ルール定義」を開閉する。窓はエクスプローラー部の中央に初期表示（ドラッグ・リサイズ可）。窓が開いている間は、エクスプローラーのキー操作を止める。
- 一覧は、ルールごとのカード（名前・概要 `条件 N件（いずれか/すべて） / 無効: … / 有効: …`）。カード内のボタン:
  - `● 有効` / `○ 無効`: 押すと切り替わり、そのつど保存する。**効果が空のルールは、有効にできない**（トーストで知らせる。無効のルールは効果が空でもよい）
  - `編集`: 編集画面（下の「編集画面（R4-b・P5）」）を、同じ窓の中で開く
  - `削除`（赤字）: 押すと、カード内が「このルールを削除する? / 削除する / やめる」に変わる。「削除する」で削除・保存する
- 「既に設定したルールをコピーして編集」: コピー元のリストボックス＋`コピー開始`。選んだルールの条件と結果を引き継いだ新しいルール（名前は `元の名前 のコピー`。同名があれば ` 2`, ` 3`…）を一覧の末尾に足して保存し、トースト「『…』をコピーしました」を出す。有効/無効も引き継ぐ。コピーしたあと、そのまま編集画面（①名前）を開く
- `初期ルールを足し直す`: 削除した初期ルールを、「無効」で足し直す（同じ名前があれば足さない）。足せるものが無ければ、トーストで知らせる
- `再読込`: 設定フォルダの `nekoviewer_tag_rules.json` を読み直す（ファイルが無ければ、ルールを空にする。壊れている・新しい版のときは、いまのルールを残してトーストで知らせる）。アプリの再起動は不要
- 保存に失敗したときは、変更を反映せず、トーストで知らせる
- すでに開いている取得の確認ウィンドウには、反映されない（次の取得から有効）

### 初期ルール（同梱）
- ルールファイルが**無い初回の起動だけ**、次の8個を、すべて「無効」で作って保存する: AI generated／cosplay／画集・イラスト集／3D / CG集／doujinshi／manga／anthology／cosplay（ファイル名の形）。全部消して空にしたあとは、作り直さない（足し直しのボタンを使う）。壊れている・新しい版のファイルは、上書きしない
- 効果が決まっているのは、AI generated・cosplay・anthology・cosplay（ファイル名の形）。他は条件だけのひな形（効果は空）で、コピー元にできる
- 無効のルールは、何も成立させないので、初期ルールだけのときの取得結果は、従来と同じ

## 手動テスト（R4-a・P4）
1. ルールファイルを消して起動し、`タグ抽出ルール定義開始` を開く → 8個のカードが、すべて `○ 無効` で並ぶ。メニューの右に `有効 0件 / 全8件`
2. `AI generated` の `○ 無効` を押す → `● 有効` になり、メニューの件数が `有効 1件 / 全8件` になる。アプリを再起動しても保たれる
3. `manga`（効果が空）を有効にしようとする → 有効にならず、トーストで「効果が空のため、有効にできません」と出る
4. `編集` を押すと、編集画面が開く（下の手動テスト（R4-b・P5）へ）
5. `anthology` の `削除` を押す → 赤字の確認が出る。`やめる` で戻る。`削除する` で消える
6. `初期ルールを足し直す` → `anthology` が、無効で末尾に戻る。もう一度押すと「足す初期ルールはありません」
7. コピー元に `cosplay` を選んで `コピー開始` → 末尾に `cosplay のコピー` が増え、トーストが出る。もう一度押すと `cosplay のコピー 2`
8. 設定フォルダのルールファイルを手で書き換えて `再読込` → 反映される。壊すと、いまのルールが残り、トーストが出る
9. 取得を実行 → 無効のルールだけのときは、従来と同じ結果。`AI generated` を有効にしたあとは、`[AI Generated]` を含むファイルの作者・グループ・イベントが未採用・要確認になる

## 編集画面（R4・P5〜P6）
- ステップ式。同じ窓の中で、一覧と切り替える。ステップは ①名前 → ②条件 → ③結果 → ④確認。ステップ表示を押すと直接移れる。下の `戻る` / `次へ` でもめくれる。
- 編集は下書きに対して行う。**④確認の `保存して一覧へ`** で保存する。`← 一覧へ` や窓の `×` は、未保存の変更があれば、確認（「破棄する」「編集を続ける」）を出す。
- ①名前: ルール名（前後の空白は除く）。有効/無効と削除は、一覧のカードから行う。
- ②条件:
  - 条件は2種類。「文字列」（`を含む` / `で始まる` / `と一致する`）と、「ファイル名の形」（`X - Y` / `X - Y (Z)` / `X - Y - Z`）。`+ 文字列の条件` `+ ファイル名の形` で足し、`削除` で外す。
  - **対象は選ばせない**。新しく作る条件は、4つの対象（ファイル名・info.txtの見出し行・info.txtのCategory・題名）をすべて見る。
  - 対象を限定した既存の条件（初期ルールの doujinshi・manga の「Category のみ」など）は、そのまま保持し、「対象を限定中: …」と表示する。変更はできず、`限定を解除` を押すと全対象になる。
  - 条件が2つ以上のときだけ、「いずれかに当てはまる / すべてに当てはまる」を選べる。
- ③結果: 種類ごとに、当てはまったときの効果を選ぶ。2つのグループに分けて並べる。
  - 従来の種類（形式・メイン・言語・イベント・作者・グループ）と、属性・年月: `そのまま` / `無効` の2択。何もしなくても取る種類なので、「有効」は無い。「無効」にした種類の言及は、候補から外れ、「未採用・要確認」で残る
  - 新しい種類（演者・キャラ・パロディ元）: `そのまま` / `有効` / `無効` の3択。普段は取らず、「有効」にしたルールが当てはまったファイルだけ取る。「無効」は、他のルールが有効にしたものを打ち消す
  - 無効と有効の両方にはならない。JSON にある、効かない「有効」の指定（従来の種類への「有効」）は、表示せずにそのまま保持する
- ④確認: ルールの内容（名前・条件の件数・効果）と、**ためし判定**。
  - ためし判定の入力は、ファイル名・info.txt の見出し行（複数行可）・info.txt の Category の3欄（保存しない）。ファイル名が空のときは判定しない
  - 結果は「当てはまる／当てはまらない」、条件ごとの ✔/✖、効果（無効・有効にする種類）。判定は、編集中の下書きのルールだけで行い、実際の取得と同じ評価（`applies_to`）を使う。ルールが無効のときも、条件に当てはまるかは試せる（効果は、有効にしたと仮定して表示し、その旨の注記を出す）
- 入力の誤りは、ステップ表示に `❗`（赤）を付け、理由を赤字で出す。誤りがある間は `保存して一覧へ` を押せない（ホバーで理由）。誤り: 名前が空（①）／同名のルールがある（①）／条件が無い（②）／文字列が空の条件がある（②）／**有効なルールの効果がすべて「そのまま」**（③。「効果を1つ以上選ぶか、一覧で無効にしてください」）。
- 一覧の `+ 空のルール`: 「新しいルール」（同名があれば ` 2`…）を、無効・条件1つ（空）・効果なしで作る下書きを開く。保存するまで、一覧には入らない。効果は③結果で選ぶ。効果を選んで保存したあと、一覧のカードで有効にする（効果が空のうちは、有効にできない）。
- 保存の失敗は、トーストで知らせ、変更は反映しない。

## 手動テスト（R4・P5）
1. 一覧で `anthology` の `編集` を押す → ①名前の画面。窓タイトルに「— anthology」が出る
2. 名前を空にする → ①に `❗` が付き、「ルールの名前を入力してください」と赤字が出る。`次へ` で②に移ると、`保存して一覧へ` が押せない（ホバーで理由）
3. 名前を、別のルールと同じにする → 「同じ名前のルールがあります」。直すと `❗` が消える
4. ②で、文字列を空にする → ②に `❗`。条件を全部 `削除` すると「条件がありません」
5. `+ 文字列の条件` で `AI` を入れ、`で始まる` に変える。条件が2つになると、「いずれか / すべて」が出る
6. `+ ファイル名の形` で `X - Y (Z)` を選べる。説明に区切りが「 - 」とある
7. `doujinshi` の `編集` → ②の条件に「対象を限定中: info.txtのCategory」が出る。`限定を解除` を押すと、表示が消える
8. 変更して `← 一覧へ` を押す → 確認が出る。`編集を続ける` で戻る。`破棄する` で、変更を捨てて一覧に戻る。窓の `×` でも同じ確認が出る
9. 変更せずに `← 一覧へ` を押す → 確認なしで一覧に戻る
10. `保存して一覧へ` を押す → トースト「ルールを保存しました」。一覧の概要が変わる。アプリを再起動しても保たれる
11. `+ 空のルール` → 「新しいルール」の編集画面。文字列に何か入れて保存 → 一覧の末尾に、`○ 無効` で増える。保存せずに一覧へ戻ると、増えない
12. コピー元を選んで `コピー開始` → トーストが出て、コピーの編集画面（①名前）が開く
13. 新しく作ったルールの `○ 無効` を押す → 効果が空のため、有効にならず、トーストが出る

## 手動テスト（R4・P6）
1. `cosplay` の `編集` → ステップ表示で `③ 結果` を押す。2つのグループが出る。従来の種類は `そのまま` / `無効` の2択（作者・グループ・イベントが `無効`）、演者・キャラ・パロディ元は3択（`有効`）
2. 演者を `無効` にすると、`有効` から `無効` に切り替わる（両方にはならない）。`そのまま` に戻せる
3. `④ 確認` を押す → ルールの内容が出る。ためし判定の欄にファイル名 `[Circle (Author)] Book [AI Generated].zip` を入れる → AI generated ルールなら「当てはまる」と ✔、効果（無効にする種類）が出る
4. `AI generated` を含まないファイル名にすると、「当てはまらない」と ✖ が出る。info.txt の見出し行に `[AI Generated]` を入れると、当てはまる
5. `doujinshi` の `編集` → ④で、ファイル名だけ入れると当てはまらない。info.txt の Category に `Doujinshi` を入れると当てはまる
6. 無効のルール（`manga`）の④でためし判定 → 注記「このルールは無効のため、実際の取得では成立しません」が出る
7. 有効なルールで、③の効果をすべて `そのまま` にする → ③に `❗` が付き、「効果がありません…」と赤字。④の `保存して一覧へ` が押せない。どれか1つ `無効` にすると、押せる
8. 新しい空のルール → ②で文字列を入れ、③で効果を選び、④で `保存して一覧へ` → 一覧に `○ 無効` で増える。カードの `○ 無効` を押すと、`● 有効` になる
9. 有効にしたルール（例: AI generated）で、取得を実行 → 確認ウィンドウで、ルールの効果が反映される（作者・グループ・イベントが未採用・要確認）

## 実機確認（ルールを書き出して試す場合）
- 効果の既定があるプリセット3つと、cosplay のファイル名の形のルールを、設定フォルダに書き出す
  `NEKO_RULES_OUT=<設定フォルダ> cargo test export_default_preset_rules -- --ignored --nocapture`（既存のルールは上書き）
- アプリを再起動し、`🏷 タグ管理` → `現フォルダファイルのタグ自動抽出＆付与` を押す

## 手動テスト（R2）
1. ルール無し（`nekoviewer_tag_rules.json` が無い）で取得すると、従来と同じ結果になる
2. 上のコマンドでルールを書き出して再起動。ファイル名に `[AI Generated]` を含むアーカイブ（例: `[Circle (Author)] Book [AI Generated].zip`）を含むフォルダで取得する
3. 確認ウィンドウ上部に「大ルール適用: AI generated 1件」が出る
4. そのファイルの作者・グループ・イベントが未採用で、「要確認: ルール「AI generated」で無効」と出る。形式（zip）と言語は採用のまま
5. 同じ作者名を持つ、ルールに当たらないファイルがあれば、その作者は採用のまま
6. info.txt の `Category: Cosplay` を持つアーカイブでは、作者・グループ・イベントが「要確認: ルール「cosplay」で無効」になる
7. 題名に `Anthology` / `アンソロジー` を含むと、作者・グループが「要確認: ルール「anthology」で無効」になる
8. 「すべて採用」を押すと、要確認の候補も採用される（確認の上で使う）
9. 「未確定のみ表示」にチェックすると、要確認の候補も出る
10. マスタに同じ作者名のタグがあっても、ルールが当たったファイルでは未採用のまま
11. しきい値スライダーなどで確認ウィンドウを作り直しても、同じルールが適用される

## 手動テスト（R3）
1. 上のコマンドでルールを書き出して再起動する
2. `Tiny Asa アサ - Castorice (Honkai-Star Rail).zip` のようなファイルがあるフォルダで取得 → 窓2に「演者」の `Tiny Asa アサ`、窓1に「キャラ」の `Castorice`、「パロディ元」の `Honkai-Star Rail` が出て、初期採用になる（`cosplay（ファイル名の形）` が成立）
3. info.txt が `Category: Cosplay` で、見出しが `希尔薇 - w旗袍 - Arknights` のアーカイブ → 演者 `希尔薇`、キャラ `w旗袍`、パロディ元 `Arknights`。作者・グループ・イベントは要確認（ルール「cosplay」で無効）。形式・言語は採用のまま
4. 見出しが `演者 - キャラ`（2つだけ）のときは、パロディ元の候補が出ない
5. 見出しが ` - ` 区切りでない cosplay（Category だけ Cosplay）は、新種類を取らない
6. 英語行・日本語行の2行で同じ形なら、`カストリス|Castorice` のように別名つきで登録される
7. マスタに「演者」「キャラクター」「パロディ元」のカテゴリがあれば、そこに照合・追加される。無ければ、適用時にカテゴリが作られる
8. 通常の同人誌（`[サークル (作者)] 題名`）は、これまでと同じ結果のまま
