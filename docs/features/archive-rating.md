# アーカイブ評価・訪問回数

アーカイブ（zip/rar/7z等）を最後まで見たときに★で評価でき、サムネカードの帯とエクスプローラー下段の
フィルタで活用する機能。あわせて、ファイルを開いた回数（訪問回数）を記録する。
単品の生画像ファイルは評価の対象外（評価UIを出さない）。訪問回数は生画像も数える。

## 評価値

- 半星単位の整数で扱う: `0` = 未評価、`1..=10` = ★0.5〜★5.0（`rating_half`）
- 「未評価」と「一度も開いていない（NEW）」は別の状態。前者は評価0のレコード、後者はレコード不在
- 触らない限り評価は書かない（未評価状態を維持する）

## ビューアの評価オーバーレイ

- 表示条件（[rating_overlay.rs](../../src/rating_overlay.rs) `overlay_visible`）: スコアリングがONで、生画像でなく、
  最終ページ（見開きなら最終ページを含む見開き）を表示中で、かつXで閉じていない
- ビューア中央に半透明の灰色帯を出し、その上に★5個（白枠。塗りは黄）を置く。
  右上に✕、★の下側中央に「未評価にする」ボタン
- ★をクリックすると、その位置まで塗る。星の左半分 = x.5、右半分 = x.0（半星は左半分だけ黄）
- クリックした瞬間にDBへ書く。値は絶対値の上書きなので、連打・押し直しでも結果は同じ（冪等）。
  既に評価があるアーカイブでも、保存値で塗った状態で出る（押せば上書き）
- 「未評価にする」は評価0を書き、トースト「未評価として登録しなおしました」を出す。既に未評価でも出す
- ✕はそのビューアを開いている間だけ非表示にする（再度評価したいときは開き直して最終ページへ行く）。
  DBには触れない
- 帯の上のクリック・ホバーは、ページ送り・ダブルクリック原寸切替・左右端ページ送りゾーンへ伝えない

## スコアリングのON/OFF

- エクスプローラーのメニューバー、`ツールボックスON/OFF` の左隣の `スコアリングON/OFF` ボタンで切り替える
  （`MenuBarButton::ScoringToggle`）。評価システム自体が邪魔な人向けの永続設定で、既定ON
- state キーは `rating_overlay_enabled`（`ViewerConfig` の項目）。旧stateにキーがなければON
- OFF の間は、アーカイブ末尾の評価オーバーレイだけを出さない（表示中に切り替えても消える）。
  訪問回数の記録・サムネの評価帯（info2）・score filter・保存済みの評価値は変わらない

## サムネカードの評価帯（info2）

- メニューバーの情報トグルの右隣にある `情報2` ボタンで循環する
  （`CardRatingMode`）: `OFF → ★ → 回数 → ★+回数 → OFF`。state キーは `card_rating_mode`
  （`off / stars / visits / stars_visits`）
- 既存の情報帯（ファイル名・日付・サイズ）の下段に、評価の行を足して1枚の帯にする。情報がOFFでも
  評価行だけの帯が出る
  - 星の行: 塗った星だけを中央寄せで並べる（空の星は描かない。半星対応）。未評価は「未評価」の文字。
    生画像は「-」（レイアウトは揃える）
  - 回数の行: 「訪問回数：XX回」を中央に置く。一度も開いていなければ0回
- 評価・訪問はキャッシュ（`archive_rating_cache`。値の `None` = レコード不在）から引く。現在フォルダは
  スキャン時に一括ロードし、お気に入り・検索結果などの横断一覧は描画時に遅延取得する。
  ビューアで評価・訪問が変わると、該当パスを即更新する

## 評価フィルタ（score filter）

- エクスプローラー下段のフィルタ行: `filter: [☑][文字列] │ score filter [☑][==▾][★N▾]`
  （縦線の右に評価フィルタ群、右端に少し余白）。チェックボックスで評価フィルタを一括ON/OFFする
- 比較は `==`（一致）/ `<=`（以下）/ `>=`（以上）、基準は★0.5〜★5.0の10項目
  （[rating_filter.rs](../../src/rating_filter.rs)）
- 文字列フィルタとAND結合する。未評価とNEW（一度も開いていない）は、有効時にどの条件にも一致しない
- 評価フィルタの状態は state に保存しない。ビューアで評価を書いても絞り込み結果はその場では更新せず、
  次のフィルタ操作か再スキャンで反映される（選択が飛ぶのを避けるため）

## 訪問回数

- アーカイブ・生画像を問わず、ビューアを開く（`open_viewer`）たびに+1し、最終訪問日時も更新する。
  同じアーカイブ内のページ送りは数えないが、ビューア内のファイル移動（前後のファイルへ）は開くたびに数える
- 記録は評価とは独立した項目。訪問だけがあって未評価のレコードが正常な状態

## 評価順・訪問回数順のソート

- メニューバーのソート軸は独立した2セット。`[名前][日付][サイズ] : [昇降] │ [スコア][訪問回数] : [昇降]`
  （[explorer_sort.rs](../../src/explorer_sort.rs)）
  - 第1セット（名前・日付・サイズ）は常に有効。従来どおりの並び
  - 第2セット（スコア・訪問回数）は既定OFF。押し下げ中の軸をもう一度押すとOFF、もう一方を押すと切り替わる（排他）
- 第2セットがONの間は、それが主軸になり、同順位を第1セットで並べる（例: スコア降順＋名前昇順）。
  昇降は各セット独立。第2セットがOFFの間、その昇降ボタンはグレーアウト（キーボード移動でも飛ばす）
- 未評価と一度も開いていないもの（レコード不在）は、スコア0・訪問回数0として並べる
- 初期の向きは降順（高い順・多い順）。ON/OFFと向きは state（`rating_sort_key` = off/score/visits、
  `rating_sort_ascending`）に保存する。旧stateや壊れた値はOFF・降順
- お気に入りの先頭固定は従来どおり最優先。フォルダカードは第1セットだけで並べる（第2セットは無視）
- 横断一覧（お気に入り・検索結果）を評価で並べるときは、評価をフォルダ単位でまとめて取り込む
- 並び直しのタイミング: ソート操作時とスキャン時。ビューアーで評価・訪問が変わっても表示中は並べ替えず、
  ビューアーを閉じたときに再ソートする。選択・複数選択・カーソルは同じファイルを指し直す

## 保存（DB）

保存先は `nekoviewer_spread.redb`（[spread_state.rs](../../src/spread_state.rs)）。

```
archive_rating_v1: &str -> (u8, u32, i64)
  キー = "{正規化済みディレクトリ}\0{ファイル名}"
  値   = (rating_half, visit_count, last_visit_at(unix秒))
```

- `record_archive_visit`（訪問+1）、`write_archive_rating`（絶対値で書込み。0で未評価、上限は10へ丸め）、
  `read_archive_rating`、`list_dir_archive_ratings`（フォルダ単位の一括取得）、`archive_rating_gc_dir`
- GC はディレクトリスキャン完了時（[scan.rs](../../src/view_explorer/scan.rs)）に、消えたファイルのレコードを削除する。
  ファイルのリネーム・移動で評価は失われる（キーがファイル名のため。しおり等と同じ挙動）
- 値形式を変える場合はこのテーブルを変更せず、`archive_rating_v2` のような新テーブルを追加して移行する
