# 重複・曖昧の解決UI（レイアウト仕様）

ファイルID（フィンガープリント）管理で、自動では決められなかった項目を、ユーザーが選んで解決する画面。
データ層・ワーカー側の仕様は [file_identity.rs](../../src/file_identity.rs) を参照。実装はブランチ
`feat/fingerprint-conflict-resolution`。この文書は、実装前に合意したレイアウトと文言の記録。

## 文言の方針

この画面が扱うのは「このアプリの管理データ（DB）に登録されたファイル」だけで、ストレージ全体の重複検索ではない。
ユーザーが勘違いしないよう、説明文・見出し・通知には必ず「管理データ（DB）内」の限定を入れる。
管理データに記録のないファイル（まだ一度も表示していないフォルダ等）は対象外。

## 未解決の種別

| 種別 | 対象 | 候補 | 確定すると |
| --- | --- | --- | --- |
| 引き継ぎ元の選択 | 新しく現れたファイル | 同内容の現存ファイル（データが食い違う複数） | 候補のデータを対象へ複製（★・しおり・見開き・ソート・登録サムネ・タグ・サムネ。訪問回数は0、**お気に入りは複製しない**） |
| 移動元の選択 | 新しく現れたファイル | 同内容の消えているファイル（移動元の候補が複数） | 選んだ候補のデータ（お気に入り含む）が対象へ移る。他の候補は未確認のまま |
| お気に入りの引き継ぎ | 実体の無いお気に入り（旧パスを表示） | 同内容の現存ファイル | お気に入りを選んだファイルへ移す |

どの場合も、解決するまで対象の新ファイルはデータが空のまま。誤った引き継ぎは起こさない。

## 入口

メニューバーの「サムネイル n/m」の**左**に「DB内の重複の解決（n）」ボタンを置く（`DB内の重複の解決（3）  サムネイル 120/480`）。
常に表示し、未解決が0件のときはグレーで押せない（未解決が出たときだけ押せる）。数字は未解決の総数。検出直後に通知トースト（「管理データ内に同じ内容のファイルが複数あり、引き継ぎ元を決められませんでした（n件）」）を出す。
件数が増えたときだけ再度出す。

## 流れ

```
[DB内の重複の解決（n）] → 第1ダイアログ（未解決の項目の一覧）
   行を選択 → [解決へ進む]（ダブルクリック・Enterでも可）
   → 第2ダイアログ（参照元の選択。第1の上に重ねる）
        行を選択 → [選択した項目を参照元として確定する] ＝ 最終意思確認
   → 適用して第2を閉じ、第1の一覧から項目を除き、★・評価帯・サムネを再読み込み
```

## 第1ダイアログ: 未解決の項目

```
┌ 未解決の項目 ────────────────────────────────────────────────────────────┐
│ このアプリの管理データ（DB）に登録されているファイルの中に、同じ内容のものが複数あり、│
│ 自動では決められなかった項目です。（ストレージ全体の重複検索ではありません）        │
│ 絞り込み: [☑引き継ぎ元の選択] [☑移動元の選択] [☑お気に入りの引き継ぎ]  表示 3 / 3件│
│ ┌──────────────────────────────────────────────────────────────────────┐ │
│ │ 種別              対象ファイル                  候補  検出日    削除まで │ │
│ ├──────────────────────────────────────────────────────────────────────┤ │
│ │ ▶引き継ぎ元の選択  b_copy.zip  (…/書籍/整理)      2   10/03    期限なし │ ▲
│ │  移動元の選択      c_new.zip   (…/読書/新規)      3   10/02    残り 41日│ █
│ │  お気に入りの引継  d_old.zip   (…/保管)           1   10/01    残り  6日│ █
│ └──────────────────────────────────────────────────────────────────────┘ ▼
│                                          [解決へ進む]      [閉じる]       │
└──────────────────────────────────────────────────────────────────────────┘
```

- 列: 種別 / 対象ファイル（ファイル名＋親フォルダ末尾。ホバーでフルパス）/ 候補数 / 検出日 / 削除まで。
- 並びは検出日の新しい順。1行選択。↑↓で移動、Enterで「解決へ進む」、Escで閉じる。
- 絞り込みは種別のチェックボックス（既定は全てON）。「表示 n / 全 m 件」を出す。
- 0件のときは「未解決の項目はありません」を中央に出す。ウィンドウが小さいときは縦横スクロール可能にする。
- 「削除まで」は、対象が「消えているID」の項目（移動元の選択・お気に入りの引き継ぎ）にだけ「残り n 日」を出す。7日以下は警告色。
  引き継ぎ元の選択は、候補が現存ファイルなので「期限なし」。

## 第2ダイアログ: 参照元の選択

```
┌ 参照元の選択 ─ 引き継ぎ元の選択 ────────────────────────────────────────┐
│ 対象ファイル                                                              │
│   b_copy.zip   /home/…/書籍/整理   12.3MB  2026-10-03 14:20               │
│                                                                          │
│ 管理データ内の、同じ内容のファイル（参照元の候補）                         │
│ ┌──────────────────────────────────────────────────────────────────────┐ │
│ │ 選択 パス                       状態  サイズ  更新日時   ★  タグ  お気に入り│ │
│ │ (●)  …/書籍/原本/b.zip           現存  12.3MB 10/01 09:10 ★4   2    あり │ ▲
│ │ ( )  …/バックアップ/b.zip        現存  12.3MB 09/20 18:02 ★2   0    なし │ █
│ └──────────────────────────────────────────────────────────────────────┘ ▼
│ 確定すると：「b_copy.zip」に、選択した参照元の★・タグ・しおり・見開き・     │
│ ソート・登録サムネを複製します（お気に入りは複製しません）。               │
│  [選択した項目を参照元として確定する]   [引き継がない（空のまま）]  [戻る]  │
└──────────────────────────────────────────────────────────────────────────┘
```

- 候補の行: 選択（ラジオ）/ パス / 状態（現存・消えている）/ サイズ / 更新日時 / ★ / タグ数 / お気に入りの有無。サムネは出さない。
- 候補の一覧もスクロールバー付き。1つだけ選択できる。
- 「選択した項目を参照元として確定する」は未選択のあいだ無効。押すと適用して閉じる（確認ダイアログは重ねない。直上の説明文が確認の役割）。
- 「引き継がない（空のまま）」は、未解決の記録を消して、新ファイルを空のまま確定する。
- 「戻る」は何もせず第1ダイアログへ戻る（保留）。
- 確定の説明文は種別ごとに変える（上表の「確定すると」）。お気に入りの引き継ぎでは、対象の欄に旧パス（実体なし）を出す。

## 削除までの日数

- 未確認IDの保持日数は **1〜120日、既定60日**（キャッシュ整理の実装時に設定項目へ。それまでは定数）。
- 残り日数 = 保持日数 − (今 − 対象IDの最終確認日)。0以下は「次回整理で削除」と表示する。
- 日数による削除でIDがDBから除かれ、候補が尽きた項目は、一覧を開くとき（再読み込み時）に自動で消える。

## 文言（日本語。英・中は実装時に同じ構成で用意する）

- ボタン: DB内の重複の解決（n）／解決へ進む／閉じる／選択した項目を参照元として確定する／引き継がない（空のまま）／戻る
- 種別: 引き継ぎ元の選択／移動元の選択／お気に入りの引き継ぎ
- 列: 種別／対象ファイル／候補／検出日／削除まで／選択／パス／状態／サイズ／更新日時／★／タグ／お気に入り
- 削除まで: 期限なし／残り n 日／次回整理で削除

## ダイアログの文面の方針

「なぜ自動では決められないか」（入口）と、「どうするとどうなるか・なぜ必要か」（出口）を、必ず文章で伝える。

- **第1ダイアログ**: 冒頭で、アプリが「内容で同じファイルを見分けて記録を引き継いでいる」こと、同内容のファイルが複数あると
  「どれがどれの続きか」を自動では決められないことを説明する。補足で、ストレージ全体の重複検索ではないこと、解決しなくても使えること
  （解決するまで該当ファイルは記録なしで表示される）を書く。一覧の下に「削除まで」の意味（見つからないファイルの記録が自動削除されるまでの日数。削除されると候補は選べなくなる）を書く。
- **第2ダイアログ上部（枠）**: 「何が起きたか」「なぜ自動では決められないか」「していただくこと」の3項目。
- **第2ダイアログ下部（枠）**: 「確定すると」「『引き継がない（空のまま）』にすると」「『戻る』と」の3項目で、各ボタンの結果を先に読めるようにする。
- 種別ごとの要点:
  - 引き継ぎ元の選択: 候補ごとに記録が違うので、誤ると別ファイルの評価・タグが付く。確定すると選んだ記録を複製（以後は別々。お気に入りは複製しない）。
  - 移動元の選択: どれが移動してきたか決められない。誤ると記録を取り違える。確定すると選んだ記録（お気に入り含む）が移り、選ばなかった候補は保持日数後に削除される。
  - お気に入りの引き継ぎ: 移動か、コピー後に元を消したのか区別できない（移動ならファイルを開いた時に自動で追従する）。確定するとお気に入りが選んだファイルへ移る。

## 実装メモ（本実装）

- 一覧は未解決の記録（`identity_pending`）から作る。一覧を開くとき（と解決の適用後）に、意味を失った記録の掃除と、
  「お気に入りの引き継ぎ」候補の検出（実体の無いお気に入りに同内容の現存ファイルがある）を行ってから組み立てる。
- 確定は `identity_resolve::apply`。成功したらサムネ（複製元・移動元に生成済みのもの）を引き継ぎ、★・評価帯・
  見開き等の表示と並びを引き直す。失敗時は理由をトーストで知らせる（既に解決済み・対象に記録が付いた等）。
- 文言は i18n（日・英・中、`idres_*`）。
