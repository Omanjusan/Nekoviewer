# 検索条件の履歴（保存・復元）

検索タブの履歴に、検索の**条件だけ**を保存する。結果（ヒット）は保存しない。履歴の行を選ぶと、条件をフォームへ復元して**再走査**する。
呼び出しの導線を短くするための機能。

実装: [search_history_store.rs](../../src/search_history_store.rs)（保存の形式と読み書き）、
[search_history_ui.rs](../../src/view_explorer/search_history_ui.rs)（復元・上限・再実行・空条件の判定）。

## 保存

- 検索を**始めた時点**で、別スレッドが条件を積む。完了や中断は待たない（中断した検索の条件も残る）。
- 置き場所: 設定フォルダ直下。**新モードと旧モードは別ファイル**。
  - `search_history_new.jsonl`
  - `search_history_legacy.jsonl`
- 形式: JSON Lines。1行=1条件。先頭が最新。
  - 新: `{"v":1,"t":保存時刻(unix秒),"text":…,"size_min":…,"size_max":…}`
  - 旧: `{"v":1,"t":…,"base_dir":…,"name":…,"subdirs":…,"size_min":…,"size_max":…,"date_after":…,"date_before":…}`
- 上限は**ファイルごとに50件**。超えると、古い行から消える。同じ条件でも、検索のたびに1行ずつ積む。
- 書き込みは一時ファイルへ書いて入れ替える。途中で落ちても、元のファイルは壊れない。
  読み込みでは、壊れた行・知らない版の行を飛ばす（他の行は読める）。

## 復元と再実行

- 起動時に、保存された条件を履歴の行として並べる（新・旧を、新しい順に混ぜる。最大100行）。**結果は持たない**。
  ラベルは条件の名前に「↻」（再走査の印）が付く。
- 結果を持たない行を選ぶと、条件（モードを含む）をフォームへ復元して、そのまま再走査する。
  再走査した行は、元の行を置き換えて先頭へ移る（ファイルでも同じ行が重複せず先頭へ移る）。
  実行中の検索があるときは何もしない。
- 同じセッション内で結果を保持している行を選んだときは、これまでどおり再走査せず、保持している結果をすぐ表示する。
- 保持するヒットの合計が50万件を超えたら、古い行から結果を手放して「結果を持たない行」に戻す（選ぶと再走査）。
  実行中の行と、いま表示している行は手放さない。
- メモリ上の履歴も、モードごとに50件まで。

## 条件が空の検索は始められない

新・旧とも、条件が1つも入っていない検索は始められない（全件の列挙になるため）。「検索開始」が押せず、ホバーで理由が出る。

| モード | 有効な条件（どれか1つ） |
|---|---|
| 新 | 検索文字列（空白・空の引用符だけは空）／サイズの最小・最大（数値として読めるもの） |
| 旧 | ファイル名／サイズ／日付（読めるもの）。基点フォルダとサブディレクトリだけでは足りない |

## 自動テスト

- 単体: 保存の形式・ローテーション・壊れた行・同時書き込み・別ファイルの独立・置き換え、条件の有効判定、上限と手放し。
- E2E（[tests/search_e2e.rs](../../tests/search_e2e.rs)。実行は `cargo test --features test-control --test search_e2e -- --ignored --test-threads=1`）:
  - 3回検索して条件が新しい順に保存され、結果は保存されないこと。再起動で履歴が戻り、行を選ぶと条件を復元して再走査し、先頭へ移ること。
  - 空の条件では、新・旧とも検索が始まらず、履歴にも残らないこと。

| # | 操作 | 期待 | 結果 |

| 2 | 文字列に空白だけ、またはサイズに英字だけを入れる | 同じく押せない | [ ] |
| 3 | 文字列を入れる／サイズだけ入れる | 押せる | [ ] |
