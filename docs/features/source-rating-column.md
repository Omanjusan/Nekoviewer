# リストの「公開評価」列

リスト表示（[explorer-view-modes.md](explorer-view-modes.md)）に、アーカイブ内の `info.txt` にある評価（`Rating: 4.82`）を数値で出す列。
自分でつける評価（★。「評価」列）とは別で、すぐ右隣に並ぶ。**リスト表示にだけ反映**する（カード・ビューアーには出さない）。

関連: 記録の仕組みは [archive-detail-pages-txt.md](archive-detail-pages-txt.md)（ページ数・詳細列と同じキャッシュ）、
タグ取得の走査からの記録は [bulk-tag-info.md](bulk-tag-info.md)。

実装:
[meta.rs](../../src/fs/archive/meta.rs)（`parse_info_rating`・`format_source_rating`・`read_zip_bundle`）、
[neko_dir.rs](../../src/neko_dir.rs)（`ARCHIVE_RATING_TABLE`・`SourceRating`）、
[list_view.rs](../../src/view_explorer/list_view.rs)（列・セル）、
[explorer_sort.rs](../../src/explorer_sort.rs)（ソート）。

## 1. 取得元と値

- 取得元は **zip/cbz の `info.txt` の `Rating:` 行だけ**。ComicInfo.xml・meta.json・readme.txt は見ない。
  `Favorited:`（お気に入り数）など、ほかの行は取らない。
- 行頭のキーが `rating`（大文字小文字は区別しない）の**最初の行**を使う。値の先頭の語だけを読む（`Rating: 4.8 (123 votes)` → 4.80）。
- 有効範囲は **0.00〜5.00**。範囲外・数値でない値（`NaN`・`good`・空）は「評価なし」。**0.00 は有効な値**で、数値の `0.00` として出す。
- 小数第3位以下は四捨五入し、評価×100の整数（4.82 → 482）で持つ。

## 2. 表示

| 表示 | 意味 |
|---|---|
| `4.82` | info.txt に評価あり（小数2桁の数値。★の半星刻みとは見え方が違うが、そのまま出す） |
| 薄い「－」 | 確認済みで、評価なし（info.txt が無い・`Rating:` 行が無い・範囲外） |
| 「N/A」 | 対応外の形式（7z・tar・フォルダ。詳細列と同じ。info.txt の取得は zip/cbz のみ） |
| 空欄 | 未確認（まだ開いていない・走査していない／zipが壊れていて読めなかった） |

- 位置は「評価」と「訪問回数」の間。**幅は固定**（リサイズ不可）。列幅の state（`explorer_list_cols`）は変えていない。
- 見出し: 日本語「公開評価」／英語「Source Rating」／中国語「来源评分」。ホバーで、値・「－」・「N/A」の意味が出る。

## 3. 記録

- ビューアーでアーカイブを開いたとき、と「現フォルダ内タグ情報取得」の走査（完了時、キャンセル時は処理した分）の両方で記録する。
  開いていないファイルでも、走査したフォルダなら列が埋まる。
- 記録先は、フォルダ別 `cache.redb` の **`archive_rating_v1`**（キー=ファイル名、値=(mtime, size, 評価×100)。`u32::MAX` は「確認済みで評価なし」）。
  詳細・ページ数の `archive_meta_v1` は値の型を変えると既存DBが開けなくなるので、別の表にしてある。
- 読むとき（`read_all_archive_meta`）は、評価の行の mtime・size が `archive_meta_v1` の行と同じときだけ有効（違えば未確認）。
  ファイルが更新されると、記録し直すまで空欄に戻る。
- 評価が未確認のときは、評価の表を触らない（走査で読めなかった場合に、既存の確認結果を消さない）。
- **この機能より前に記録したファイルは、開き直すか走査するまで空欄**（`archive_rating_v1` に行が無いため）。

## 4. ソート

- 「公開評価」見出しのクリックと、ソートメニューの `[公開評価]`（英 `[Source Rating]`、中 `[来源评分]`）で並べ替える。
  **評価の第2セット**（スコア・訪問回数・ページ数と同じ）に `SourceRating` を足した。降順 → 昇順 → OFF の順に切り替わる。
- 未取得・評価なしは0として扱う。昇順にすると、それらが先頭に集まる。0.00 も同じ並び（値としては0）。
  同順位は第1セットの条件で並ぶ。
- state の `rating_sort_key` に `source_rating` が入る。旧版は未知の値として OFF 扱いになる。
- ソートに使う値は、記録が現物と合うときだけ。古い記録は0扱い。

## 未対応・注意

- 7z・tar・フォルダは取得できない（列は「N/A」）。
- info.txt の `Rating:` 以外（XML・JSON の評価、`Favorited:`）は対象外。
- 旧記録のファイルは、再オープンか走査まで空欄。
- 記録は cache.redb（ファイル名キー）のため、ファイルの改名・移動では引き継がれず、開き直すと再記録される。

## 自動テスト

- `meta.rs`: `parse_info_rating`（小数・範囲外・0.00・注記つき・最初の行だけ）、`format_source_rating`、info.txt だけから評価を拾うこと（readme.txt は見ない）。
- `neko_dir.rs`: `SourceRating` の往復、更新日時が違う古い行の無視、走査の一括書き込みと「未確認なら既存を残す」、ソート用の値。
- `tag_scan.rs`: 走査が info.txt の評価（有り・無し・壊れたzip・フォルダ）を持つこと。
- `explorer_sort.rs`: 公開評価のソート順（0を先頭に集める）、state キー、見出しの遷移、`needs_*` の判定。
- `list_view.rs`: 列の並び・固定幅・ソート対象であること。

## 手動テスト手順

テスト用に、info.txt の内容だけが違う zip を用意する（`Rating: 4.82`／`Rating: 0.00`／`Rating: 5.01`／`Rating: good`／Rating 行なし／info.txt なし）。

1. 開く前は、どのファイルも「公開評価」が空欄。
2. 評価と訪問回数の間に「公開評価」列がある。幅は固定で、ドラッグしても変わらない。英語・中国語表示でも見出しが列に収まる。
3. `Rating: 4.82` のzipを開いて閉じると `4.82`。`Rating: 0.00` は `0.00`。
4. `Rating: 5.01`・`Rating: good`・Rating行なし・info.txtなしは、薄い「－」。
5. 7z・tar・フォルダを開いて閉じると「N/A」。
6. セルにマウスを重ねると、値・「－」・「N/A」それぞれの説明が出る。
7. 一度も開いていないフォルダで「現フォルダ内タグ情報取得」を実行すると、完了時に公開評価が埋まる（開いていないファイルも）。詳細列・ページ数列も同時に埋まる。
8. 走査の前に開いていたファイルの値が、走査のあとも変わらない。
9. ファイルを更新（touch など）してフォルダを開き直すと、そのファイルの公開評価が空欄に戻る。開き直すか走査すると再記録される。
10. 「公開評価」見出しを押すと、評価の高い順（降順）→ 低い順（昇順。未取得・評価なし・0.00 が先頭）→ OFF。▲▼が出る。ソートメニューの `[公開評価]` でも同じ。再起動しても並びが残る。
11. 公開評価でソート中は、評価・訪問回数・ページ数のボタンが OFF になる（第2セットは1つだけ）。同順位は第1セット（名前など）で並ぶ。
12. 自分の評価（★）の編集（＋－）や並びが、公開評価の追加で変わっていない。カード表示・ビューアーには何も出ない。
13. この機能より前に記録していたフォルダは、公開評価が空欄から始まり、開き直すか走査すると埋まる。
