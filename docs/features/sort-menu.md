# ソート条件メニュー（ビューアー／エクスプローラー）

ソート関連のボタン群を、どちらも「展開メニュー1個」に集約した。ビューアー側は保存済みソートが無いアーカイブの
**デフォルト条件**を、メニューのチェックで直接決められる（設定画面を経由しない）。
実装は [view_reader.rs](../../src/view_reader.rs)（`draw_sort_menu` / `sort_choice_button` / `sort_order_button`）、
[panels.rs](../../src/view_explorer/panels.rs)（`draw_sort_menu` ほか）、キー操作は
[input.rs](../../src/view_explorer/input.rs)（`handle_menu_bar_keys`）と panels.rs の `handle_sort_menu_keys`。

## 共通の見た目

- 選択肢（キー）は薄いグレー背景＋枠のボタン。選択中は塗り色（基本キー＝青、評価キー＝赤）＋白文字。
- 昇順/降順は塗りなし＋青系の枠線＋矢印（`↑ 昇順` / `↓ 降順`）。キー選択と同列に見えないようにするため。
  矢印は [glyph_audit.rs](../../src/view_explorer/glyph_audit.rs) で豆腐チェックする。
- キー名は括弧なしの文字だけ（i18n 定義は `[名前]` 形式のまま、表示側で括弧を外す）。

## ビューアー：「ソート条件」メニュー

ツールバーの旧4項目（名前・自然数・日付・昇降）を `SortMenu` 1項目に集約した（[toolbar.rs](../../src/toolbar.rs)）。

```
名前    ☐ このキーをデフォルト設定する
自然数  ☐ このキーをデフォルト設定する
日付    ☐ このキーをデフォルト設定する
↑ 昇順   デフォルトの順序 [↑ 昇順]
-----------------
デフォルトキーが設定されていても、ソート条件を保存したファイルは保存された条件が優先されます。
```

- キー行のボタン／左下の昇降は**いま開いているファイル**の条件を変える（従来のボタンと同じ）。
- 「このキーをデフォルト設定する」は常に1つだけ（実質ラジオ）。ONのものを押しても外れない。全部OFFの状態は作れない。
- 「デフォルトの順序」は、デフォルトの昇順/降順。キーとは独立に切り替える。
- デフォルトを変えても、いま開いているファイルの並びは変わらない（次に開くファイルから効く）。
- 優先順位: **ファイル単位の保存済み条件（[archive-sort-state.md](archive-sort-state.md)）＞デフォルト＞名前・昇順**。
  保存済みが無いアーカイブを開くときだけ `open_viewer` が適用する。このとき保存はONにならない。
  単一画像（raw）は対象外。
- 保存先は state の `viewer_default_sort_key`（`name`/`natural`/`date`）と `viewer_default_sort_ascending`
  （`ViewerConfig.default_sort_key` / `default_sort_ascending`）。未知値・欠落は名前・昇順。
  変更時は `ViewerOutput.default_sort_changed` で app 側が即保存する。
- ツールバー項目の移行: 旧ID（`sort_name` `sort_natural` `sort_date` `sort_order`）は読み込み時に捨てられ、
  `sort_menu` が既定位置（先頭）に補完される（[viewer-toolbar.md](viewer-toolbar.md) の前方互換規則どおり）。
  項目数は15→12。

## エクスプローラー：ソート展開メニュー

メニューバーのソート関連7ボタンを、`ソート: 名前 昇順` 形式の1ボタン（`MenuBarButton::Sort`）に集約した
（`MENU_BAR_ORDER` は17→11）。評価キーがONのときは優先順に `ソート: スコア 降順 > 名前 昇順` と表示する。

```
＜基本キー＞ [↑ 昇順]
 名前  日付  サイズ
-----------------
＜評価キー（任意）＞ [↓ 降順]
 スコア  訪問回数
-----------------
評価キーがONのときは評価キーが優先され、同順位を基本キーで並べる。任意キーの条件は選択中のボタンをもう一度押すと無効化可能。
```

- 並びの意味は従来から変えていない（[archive-rating.md](archive-rating.md)「評価順・訪問回数順のソート」）。
  評価キーがONの間は評価キーが主軸、同順位を基本キー。名称だけ「第2セット」から「評価キー（任意）」に改めた。
- 評価キーは選択中のボタンをもう一度押すとOFF。OFFの間は評価キーの昇降ボタンがグレーアウトする。
- 見出しにポインタを乗せる（ヘルプON時）と、従来のヘルプ文が出る。
- エクスプローラー側に**デフォルトの概念は無い**。最後に使った条件を次回起動で復元する従来のまま
  （state の `sort_key` / `rating_sort_key` ほか）。リスト表示の列見出しソートとも状態を共有する。

### キーボード操作（メニューバー）

- バー側のカーソル（左右キー）が「ソート」に**着いた時点で自動展開**し、カーソルを最上位（基本キーの昇降）に置く。
  別のボタンへ移ると縮小する。Tab でペインを移る／Esc／メニュー外クリックでも閉じる。
- メニューが閉じている状態で、カーソルがソートにあるとき **↓** で展開し最上位へ。Enter でも開閉できる。
- メニュー内は **↑↓ だけ**で、全ボタンを1列として移動する。順序:
  基本キーの昇降 → 名前 → 日付 → サイズ → 評価キーの昇降 → スコア → 訪問回数。
  - 評価キーがOFFの間、評価キーの昇降ボタンは飛ばす（押せないため）。
  - 先頭で ↑ を押すとメニューを閉じる（バー側カーソルはソートに残る）。
  - 末尾（訪問回数）で ↓ を押しても何も起きない。上下で隣のメニュー項目へは移らない。
- **←→** はメニュー内の選択には使わない。押すとメニューを閉じ、バー側カーソルがその方向の隣へ動く。
- Enter でカーソル位置の項目を実行（クリックと同じ処理 `apply_sort_menu_item`）。評価キーのON/OFFで昇降ボタンの
  有無が変わるため、実行後は同じ項目にカーソルを追従させる。
- マウスで開いた場合はメニュー内カーソルを出さない。その状態でソートボタン上で ↓ を押すとカーソル付きになる。

## 自動テスト

- 設定の保存/復元・フォールバック: `viewer_default_sort_round_trips_and_falls_back`（gui_config.rs）。
- ツールバー項目の移行: `legacy_sort_ids_migrate_to_sort_menu` ほか（toolbar.rs）。
- メニューバー順序: `menu_bar_order_tests`（view_explorer/mod.rs）。
- 昇降矢印の豆腐チェック: `sort_order_arrow_glyphs_are_available`（glyph_audit.rs）。
- メニューの描画・キー操作・デフォルト適用は自動テストなし。下記の手動確認。
