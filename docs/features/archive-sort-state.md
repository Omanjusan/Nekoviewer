# アーカイブ単位のソート条件保存

## 対象

ビューアー内のソートキー（名前・自然順・日付）と昇順・降順を、アーカイブ単位で任意保存する。
単一画像を直接表示する raw ビューアーは対象外。

## UI

画像の右クリックメニューで、見開き状態保存と上書き保存の直下に次の3行を表示する。

```text
[チェックボックス] 現在のソート条件を保存する
新しい保存値 : 名前 降順（変更あり）
```

「変更あり」は、保存ONで現在値が保存済み値と異なる場合だけ表示する。「新しい保存値」は
次の自動保存で書き込まれる現在値を示す。

## 保存OFF

保存OFFはRDBレコード不在で表す。チェックを外すとレコードだけを削除し、現在のソート条件と
ページ位置は変更しない。未保存のアーカイブを新しく開くときは追加の復元処理を行わず、従来の
`ViewerState` 初期化ロジック（名前・昇順）をそのまま使用する。

## 保存と復元

チェックを入れたときは現在値を即時保存する。保存ONのままソートを変更した場合は、次のタイミングで
保存済み値との差があるときだけ上書きする。

- 前後のアーカイブまたは一覧上の別ファイルへ移動する直前
- EscまたはOSのクローズ操作でビューアーを閉じる直前
- アプリを終了する直前

アーカイブを開くときは、保存レコードがある場合だけ次の順で復元する。

1. 従来どおり `ViewerState` を生成する
2. 保存済みソート条件を適用する
3. 保存済み見開き状態を適用する

ソート処理はページ位置と見開きオフセットをリセットするため、見開き復元を必ず後に行う。

## RDBと世代管理

既存の `nekoviewer_spread.redb` に、見開き状態とは独立した次のテーブルを置く。

```text
archive_sort_state_v1: &str -> (u8, bool)
```

キーは既存の見開き状態と同じ「正規化済みディレクトリ + NUL + ファイル名」。値は
`(sort_key, ascending)` で、ソートキーの割り当てを次に固定する。

```text
0 = 名前
1 = 自然順
2 = 日付
```

未知の値は保存なしとして扱う。将来値形式を変更するときは既存テーブルの型を変更せず、
`archive_sort_state_v2` のような新テーブルを追加して、安全に読み込めたレコードだけを移行する。
旧テーブルは移行成功前に削除しない。
