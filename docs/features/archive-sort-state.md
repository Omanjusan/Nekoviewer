# アーカイブ単位のソート条件保存

保存が無いアーカイブの初期条件は、エクスプローラーのソートメニュー末尾「ビューアーのデフォルト（任意）」で指定した条件。
指定なしなら名前・昇順。保存済みがあればそれが常に優先する（[sort-menu.md](sort-menu.md)）。

## 対象

ビューアー内のソートキー（名前・自然順・日付・格納順）と昇順・降順を、アーカイブ単位で任意保存する。
単一画像を直接表示する raw ビューアーは対象外。

## UI

画像の右クリックメニューで、見開き状態保存と上書き保存の直下に次の3行を表示する。

```text
[チェックボックス] 現在のソート条件を保存する
新しい保存値 : 名前 降順（変更あり）
```

「変更あり」は、保存ONで現在値が保存済み値と異なる場合だけ表示する。「新しい保存値」は
次の自動保存で書き込まれる現在値を示す。

## 保存OFF

保存OFFはRDBレコード不在で表す。チェックを外すとレコードだけを削除し、現在のソート条件と
ページ位置は変更しない。未保存のアーカイブを新しく開くときは追加の復元処理を行わず、従来の
`ViewerState` 初期化ロジック（名前・昇順）をそのまま使用する。

## 保存と復元

チェックを入れたときは現在値を即時保存する。保存ONのままソートを変更した場合は、次のタイミングで
保存済み値との差があるときだけ上書きする。

- 前後のアーカイブまたは一覧上の別ファイルへ移動する直前
- EscまたはOSのクローズ操作でビューアーを閉じる直前
- アプリを終了する直前

アーカイブを開くときは、保存レコードがある場合だけ次の順で復元する。

1. 従来どおり `ViewerState` を生成する
2. 保存済みソート条件を適用する
3. 保存済み見開き状態を適用する

ソート処理はページ位置と見開きオフセットをリセットするため、見開き復元を必ず後に行う。

## RDBと世代管理

既存の `nekoviewer_spread.redb` に、見開き状態とは独立した次のテーブルを置く。

```text
archive_sort_state_v1: &str -> (u8, bool)
```

旧v1のキーは見開き状態と同じ「正規化済みディレクトリ + NUL + ファイル名」。現行は、ファイルIDをキーにした
`file_settings_v2`（見開き・ソート・登録サムネ・タグ・お気に入りを1レコードに束ねる。
[file-identity.md](file-identity.md) 参照）に保存し、旧v1の行は書き込み時に引き継ぐ。移動・リネームにも追従する。値は
`(sort_key, ascending)` で、ソートキーの割り当てを次に固定する。

```text
0 = 名前
1 = 自然順
2 = 日付
3 = 格納順
```

未知の値は保存なしとして扱う。将来値形式を変更するときは既存テーブルの型を変更せず、
`archive_sort_state_v2` のような新テーブルを追加して、安全に読み込めたレコードだけを移行する。
旧テーブルは移行成功前に削除しない。

## 格納順

ファイル名がランダム文字列のアーカイブでは、名前・自然順・日付のどれでも作者の並びを再現できない。
そこで、アーカイブ内の**格納順**（列挙順）を第4のソートキーとして持つ。自動判定はしない。
既定ソートや保存ソートとして選べる選択肢が1つ増えるだけで、選ぶかどうかはユーザーが決める。

- 格納順の連番は [finalize_entries](../../src/fs/archive/mod.rs) が名前ソートの前に振り、`ImageEntry.stored_index` /
  `ViewerEntry.stored_index` に持つ。`original_index`（サムネ・OCR・翻訳テキストのキャッシュキー）は従来どおり
  名前ソート後の位置で、格納順を選んでも変化しない。
- 格納順の意味は形式ごとに次のとおり。zip＝中央ディレクトリの順、7z＝ヘッダのファイル順、tar＝書き込み順。
  **7zは、7-Zipのソリッド圧縮が拡張子順などに並べ替えて格納することがあり、その場合は作成ツールが決めた順になる。
  アプリ側では直せない。**
- TXTページ（info.txt等）も画像ページと同じく、格納されている位置に出る。分割ページは元ファイル内のページ順。
- 降順は格納順の逆順。
- フォルダ（仮想本）と単一画像には「格納」の概念が無い（フォルダは列挙順がファイルシステム依存）。ボタンはグレーアウトし
  ホバーで理由を出す。保存値・既定設定が格納順でも、これらは**名前順で開き、保存値・設定は書き換えない**。
  この場合、保存値との差は「変更あり」と数えない。
- basename が衝突するエントリの `_01` 付与は、格納順で先のものが無印（従来はパス順）。パス順と格納順が食い違う
  アーカイブでだけ、衝突した2枚の割り当てが入れ替わる。
- ツールバー項目は `sort_stored`（日付の右・昇降の左）。state に保存済みの並びには、欠落補完で日付の直後に自動で出る。
- 実装は [view_reader.rs](../../src/view_reader.rs)（`sort_entries` / `stored_sort_available` / `restore_saved_sort`）、
  [toolbar.rs](../../src/toolbar.rs)（`SortStored`）、[spread_state.rs](../../src/spread_state.rs)（値3）、
  [gui_config.rs](../../src/gui_config.rs)（`stored`）。

| # | 操作 | 期待 | 結果 |

| S1 | ランダム名のzipを開いて `[格納順]` を押す | 作成ツールが入れた並びになる。`[名前]` で名前順に戻る | [ ] |
| S2 | 格納順で昇降を切り替える | 降順は格納順の逆 | [ ] |

| S4 | 格納順にして「現在のソート条件を保存する」→別アーカイブへ移動して戻る | 格納順で復元される | [ ] |
| S5 | フォルダ（仮想本）を開く | `[格納順]` がグレーアウトし、ホバーで理由が出る | [ ] |
| S6 | 単一画像を開く | 同上 | [ ] |
| S7 | 保存値が格納順のアーカイブと同じ設定でフォルダを開く | 名前順で開く。保存値は消えない | [ ] |
