# ウィンドウ位置メニュー（ビューアー窓の位置・サイズの記録/展開）

ビューアー上部バー右寄せの `[ウィンドウ位置]` ボタンから開くメニュー。旧 `[位置F5]`〜`[位置F8]` の4ボタンを置き換えた。
F5〜F8キーによる展開、ツールパレットのスロット展開、循環ボタンは従来どおり。
実装は [view_reader.rs](../../src/view_reader.rs)（`draw_window_pos_menu` ほか）、補正の計算は
[monitor_geom.rs](../../src/monitor_geom.rs)、モニター一覧の取得と復帰処理は [winit_app.rs](../../src/winit_app.rs)。
自動テストは [e2e-window-pos.md](../e2e-window-pos.md)。

## メニュー

```
F5  [展開]  モニター2 (1920,0) 1280×720  [記録] [削除]  ☐開いたとき自動展開
F6  [展開]  記録なし                      [記録] [削除]  ☐開いたとき自動展開
F7  …
F8  …
```

- 行頭のキー名は、`ApplySlot1〜4` に現在割り当てられているキーボード（キーアサインで変えれば追随）。未割り当ては「—」。
- **展開**: 記録した位置・サイズを窓に適用し、メニューを閉じる。記録なしの行は押せない（F5〜F8キーでも何も起きない）。
- **記録**: いまのビューアー窓の位置・サイズを記録する。メニューは閉じない。記録済みの行は上書き確認ダイアログを出す。
- **削除**: その行の記録を消す。確認なし。メニューは閉じない。記録なしの行は押せない。
- **開いたとき自動展開**: ビューアーを開くたびにそのスロットを適用する。チェックは全行で排他（全て外すと適用しない）。
  旧「設定 → ビューアーを開くときの既定の位置・サイズ」はこのチェックに統合し、設定画面からは削除した。
  保存形式（state の `app_default_slot`）は変えていない。
  - 自動展開に指定中のスロットを削除しても、チェックは外さない。空のまま残り、開いても何も適用しない。
- 表示は「モニターN (x,y) W×H」。**N は左→右、同じ x なら上→下の順の番号**で、OS のディスプレイ番号とは無関係。
  記録位置がどのモニターとも重ならないときは「モニター?」。保存形式はx/y/w/hのみで、番号は保存せず表示のたびに逆算する。

## Wayland での扱い（XWayland で起動する入口）

Wayland ネイティブでは、winit が窓の座標を取得・指定できない（`outer_position` が常にエラー、`set_outer_position` は何もしない）。
そのため **記録・展開・復帰が効かない**（旧4ボタンでも同じ）。X11 バックエンド（XWayland）なら動くので、
メニュー最上段から「次回起動時に XWayland で起動する」を選べる。実装は [display_backend.rs](../../src/display_backend.rs)。

メニュー最上段の表示は、**Wayland セッション（`WAYLAND_DISPLAY` あり）のときだけ**出る。X11 セッションと Windows には出ない。
ボタンはどちらのモードでもグレー化しない。

| 起動中のモード | 表示 | チェック |
|---|---|---|
| Wayland ネイティブ | 「Waylandで起動している場合はこの機能は動作しません。XWaylandで実行しなおしてください」 | `次回起動時にXWaylandで起動する` |
| XWayland | 「XWaylandで起動しています。」＋補助文「もし不具合が生じていると判断した場合既定のWaylandモードで実行することをおすすめします」 | `次回起動時にWaylandで起動する` |

- チェックは**状態ではなく「次回に今のモードを変えたい」という意思**。起動直後は常に未チェック。
  永続化するのは「次回の起動モード」1項目（state の `app_launch_x11`、既定 false = Wayland）。
  表示は「保存値が今のモードと違うか」で導く（`switch_pending_for`）。メニューを開き直しても意思は残る。
- 起動時に、Wayland セッションで保存値が true かつ `DISPLAY` があれば、`with_x11()` で X11 バックエンドを強制する。
  切り替えは**手動の再起動**（単一インスタンス制御があるので、今のアプリを閉じてから起動し直す）。
- 保存値が true でも `DISPLAY` が無ければ、起動を止めずに Wayland のまま起動し、メニュー最上段に
  「XWaylandが使えない（DISPLAYが見つからない）ため、Waylandで起動しました。」を出す。
- 環境変数だけで試す場合は `env -u WAYLAND_DISPLAY nekoviewer`（チェックの保存とは無関係に使える）。
- 描画の present mode（`is_wayland_session`）は、実バックエンドではなく「Wayland セッションか」で決め続ける。
  XWayland でも、Wayland コンポジタが隠れた窓の frame を返さない問題の影響を受けうるため。
- 注意: GNOME（Mutter）は X11 窓を画面内に収めるため、XWayland では窓が画面外へ行きにくい。復帰ボタンは保険になる。

## 画面外補正

展開時とビューアー起動時の自動展開で、窓の左上を補正する（[monitor_geom.rs](../../src/monitor_geom.rs) `clamp_slot_position`）。

- 基準モニターは、記録位置の窓と最も重なるもの。どれとも重ならなければ中心が最も近いもの。
- 基準モニターの内側に、横は100px以上、縦はモニター上端以降〜下端から100pxまでが残るように寄せる。
- 全モニターの一覧を見る。旧実装は「いまいるモニター」のサイズだけで制限していたため、
  2枚目のモニター上の記録が1枚目の幅で丸められていた。
- 自動展開で記録位置が画面外でも、補正のほかに勝手な移動はしない。見失ったときは下の「ビューアー復帰」を使う。
- モニター一覧が取れないときは、いまいるモニターを原点の1枚として扱う。ただし200px未満の極小モニター
  （一部のXサーバーが返すダミー）は無視して、補正しない。

## ビューアー復帰

エクスプローラーのメニューバーの `[ビューアー復帰]`（`[ツールパレット] │ [ビューアー復帰] │ [設定]` の位置）。
画面外に出て見失ったビューアー窓を中央へ戻す。窓の外にあるボタンなのは、窓が見えなくても押せるようにするため。

- ビューアーが開いていないときは灰色で押せない（キーボードの左右移動でも飛ばされる）。単発ボタンで押し下げ表示にはならない。
- 窓と最も重なる（無ければ最も近い）モニターの中央へ移す。サイズは維持し、モニターより大きいときだけ収まるよう縮める。
- 最小化中なら戻す。全画面中は何もしない。移動後にフォーカスする。

## 手動確認項目（未実施・列挙のみ）

自動テストでは確かめられない範囲。実施した結果の記録はここには書かない。

- 複数モニター環境で、メニューの「モニターN」が左→右の順で出る。
- 複数モニター環境で、2枚目のモニター上の記録を展開すると同じ位置に出る。
- モニターを1枚外した後、外したモニター上の記録を展開すると残ったモニターの内側に寄る。
- モニターを外した状態で自動展開の指定を残して起動したとき、窓が見えなくても `[ビューアー復帰]` で戻せる。
- 倍率（DPI）が異なるモニターをまたぐ記録の展開位置が大きくずれない。
- 窓マネージャー・タイトルバーのある環境（Windows、X11、XWayland）で、記録→展開した位置・サイズが同じになる。
- Wayland のネイティブ動作では窓の位置を指定できないため、展開・復帰が効かない（想定どおり）。
- Wayland セッションで、メニュー最上段の2行（警告・案内文とチェック）が出る。X11 セッションと Windows では出ない。
- 「次回起動時にXWaylandで起動する」にチェックして再起動すると、XWayland で起動する（文言が切り替わり、窓の位置の記録・展開・復帰が効く）。
- XWayland 起動中に「次回起動時にWaylandで起動する」にチェックして再起動すると、Wayland ネイティブに戻る。
- XWayland 起動での見た目（HiDPI・分数スケーリングのボケ）、日本語入力（IME）、ドラッグ&ドロップに支障がないか。
- `DISPLAY` が無い Wayland 環境で保存値が true のとき、起動できてエラー文言が出る。
- メニューの見た目: 3言語で行が崩れない、記録なしの灰色表示、上書き確認ダイアログの文言。
- F5〜F8を別のキーに割り当て直すと、メニューの行頭のキー名が追随する。未割り当てで「—」になる。
- フルスクリーン時はバーごと隠れるので、メニューは出ない（F5〜F8キーは効く）。
