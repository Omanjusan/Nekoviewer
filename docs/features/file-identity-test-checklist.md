# ファイルID管理 統合テスト手順書

仕様は [file-identity.md](file-identity.md)、解決UIは [fingerprint-resolution-ui.md](fingerprint-resolution-ui.md)。
`cargo run`（debug）で行い、「12. releaseビルド」だけ `cargo run --release`。✓ 欄に記入して使う。
旧DBに戻して繰り返せるよう、開発用DBバックアップ（[dev-db-backup.md](../dev-db-backup.md)）を使う。

## 0. 準備

- [ ] **新ビルドを最初に起動する前に**、旧パス仕様DBを手動でコピーしておく。
  `cp ~/.config/nekoview/nekoviewer_spread.redb ~/nekoviewer_spread.redb.pre-fp`
- [ ] 開発用ツール（設定→デバッグタブ→「現DBをバックアップ」）で基準バックアップを取る。FP仕様のDBは拒否されるので、最初の1回だけ。
- [ ] テスト用フォルダを用意する。
  - `T/src/` に zip を6個（`a`〜`f`）。うち1個は300KB以上、1個は5MB以上。画像（生画像）3枚。
  - `T/dst/`（空）。`T/many/` に2,000ファイル以上（性能確認用）。
- [ ] `a` に全データを付ける: 評価★4・しおり（途中ページ）・見開き保存・ソート保存・登録サムネ・タグ2つ・お気に入り（フォルダ所属）。
- [ ] `b` には評価とお気に入り（未整理）だけ。`c` には何も付けない。
- [ ] 一度終了して、サムネが生成されていることを確認する。
