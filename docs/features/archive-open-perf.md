# アーカイブを開く速度（冷たいHDD）

エクスプローラーでアーカイブをダブルクリックしてから、ビューアーに1枚目が出る（その後のページ送りが詰まらない）までの無駄を減らした。
**HDDの初回（OSのキャッシュが冷たい状態）で、大きい zip ほど遅かった**のが対象。2回目以降（キャッシュが温かい状態）は、もともと問題なかった。
結果（一覧・ページ数・並び順・表示）は変えていない。

## 1. 計測結果（冷たい初回、HDD）

| | 変更前 | 変更後 |
|---|---|---|
| 1.4GB・220件の zip：クリック→ワーカー結果 | 1280ms | 約60ms |
| 同：1ページ目の次（6.2MB の GIF）の読み | 1500〜1800ms | 約80ms |
| 796MB・118件（TXT入り）：クリック→ワーカー結果 | 4550ms | 約180ms |
| 378MB・37件：クリック→ワーカー結果 | | 約310ms（うち230msは中央ページの冷たい読みで、判定に必要な読み） |
| サムネバーのディスク読み（巨大なアニメ画像が多い本） | 1000〜3500ms（十数本が並行） | 大半 2〜180ms |

## 2. 原因（実測で切り分けた順）

| 段階 | 原因 | 対策 |
|---|---|---|
| 一覧取得（①）・メモリ見積もり（②）・ページ読み | zip クレートの `ZipArchive::new` が、開く時に全エントリのローカルヘッダをシークで読む。冷たいHDDで 1.8〜6秒。しかも①②と、各デコードスレッドの初回で別々に払っていた | §3.1〜§3.3 |
| 先頭のマジック読み（`detect_format`） | 冷たいHDDでシーク1回。しかも形式キャッシュは、読んでいる間もグローバルロックを持つので、他スレッドの判定も待たせる | §3.4 |
| FileCache の zip 丸読み | `ensure_file_cached` が zip 全体（最大数GB）を読む。ページ読みと同じディスクを取り合い、ページジョブが 1.5〜1.8 秒に跳ねる | §4.1 |
| タグパネルの選択プレビュー | ダブルクリックの1回目の選択で、同じ本の先頭画像を冷たく読み始め、開く処理と競合 | §4.3 |
| 手すき生成 | ビューアーの操作を「入力」と見ないので、ページ送り中も新規送信が続く | §4.2 |
| サムネバー（アーカイブ内サムネ） | 全ページ分を CPU 数のスレッドで同時に丸読み。いま見ているページの読みが埋もれる（読み 1567ms・デコード 6ms） | §4.4 |

デコードは 4〜45ms で、ボトルネックではない（ページ内訳のログで確認）。

## 3. 開く経路から `ZipArchive::new` を外す

タグ自動抽出の高速化（[tag-scan-perf.md](tag-scan-perf.md)）で作った「中央ディレクトリだけを末尾から読む」近道（[zip_cd.rs](../../src/fs/archive/zip_cd.rs)）を、ビューアーを開く経路にも使う。
**判断できないものは、これまでどおり zip クレート経由に戻す**ので、結果は変わらない。

### 3.1 一覧取得（`list_images_zip_with_progress`）

[zip.rs](../../src/fs/archive/zip.rs) の `list_images_zip_fast`。中央ディレクトリから、名前・更新日時・（TXT分割モードのときだけ）本文を読んで一覧を作る。
従来経路は `list_images_zip_slow` に分けて残し、等価テストの比較対象にもしている。
更新日時は MS-DOS 形式から日付キーを作る（`dos_date_key`。zip クレートと同じ範囲検査で、範囲外は 0）。

### 3.2 メモリ見積もり・ページ読み（`FastZip`）

`FastZip`（[zip.rs](../../src/fs/archive/zip.rs)）が、`ZipArchive::new` を通さずに zip を開く。末尾の中央ディレクトリだけを読み、エントリは「ローカルヘッダ＋データ」を直接読む（CRC検査つき）。
`load_bytes` は `load_bytes_from_archive` と同じ結果（生バイト・表示名・TXTページの目印つきペイロード）を返す。

使う場所:
- メモリ見積もり（`estimate_archive_memory_zip`）。サンプル3枚を `FastZip` で読む。
- ページ用デコードワーカー・アーカイブ内サムネワーカー（`OpenArchive::Fast`。[cache.rs](../../src/cache.rs)）。FileCache にまだ載っていない zip を、ディスクから開く経路。

### 3.3 近道を使わず従来経路に戻す条件

次のどれかなら、近道を使わない。

- 中央ディレクトリを自前で解析できない（ZIP64・複数ディスク・先頭に余分なデータ・サイズや件数の不整合・巨大な中央ディレクトリ）
- 名前を差し替える拡張（Unicode パス）がある
- 暗号化されたエントリ、または stored / deflate 以外の圧縮方式のエントリがある
- 画像・TXT の名前が、UTF-8 フラグ無しの非 ASCII（CP437 の解釈が要る）
- TXT 分割モードで、本文の読みに失敗した
- （`FastZip` のみ）画像・TXT に同じ名前が複数ある

**既知の差**: 従来経路は、ローカルヘッダが1件でも壊れた zip を開けず「無効なアーカイブ」にしていた。近道は一覧を作れるので、そのような zip は一覧が出て、ページ読み込みで失敗する（中央ディレクトリや末尾が壊れた zip は、これまでどおり無効になる）。

### 3.4 形式判定（マジック読み）を省く

拡張子が zip / cbz のとき、[mod.rs](../../src/fs/archive/mod.rs) の `list_images_with_progress` は `detect_format` より先に近道で一覧を作る。
近道で作れたら、そのパスを形式キャッシュへ「zip」として覚えさせる（`detect::remember_zip`）。以降の `detect_format`（見積もり・詳細読み・ワーカーの初回）は、先頭のマジック読みを払わない。
近道が使えない（7z の偽名など）ときは、これまでどおり `detect_format` を通る。

## 4. 同じディスクを取り合わせない（HDD向け）

画面に出すための読み（ページ・アーカイブ内サムネのデコード、アーカイブを開く処理）を優先し、それ以外は譲る。[cache.rs](../../src/cache.rs) の2つの印で見分ける。

- `ForegroundIoGuard`：ページ用デコードワーカー・アーカイブ内サムネワーカー・アーカイブを開く処理が、動いている間だけ持つ。
- `PageIoGuard`：ページ用デコードワーカーと、アーカイブを開く処理だけが持つ（サムネワーカーは持たない）。

### 4.1 FileCache の丸読み（`read_file_yielding`）

zip を2MBずつ読み、各区切りの前に `ForegroundIoGuard` が静かになるまで待つ（動いていない・最後の終了から150ms以上、30ms間隔で確認）。
ページ送りが続く間は、丸読みは進まない。読み終われば、これまでどおり FileCache に載る。7z/tar の展開は従来どおり（対象外）。
計測ログの `読み込み=…ms (うち譲り待ち=…ms)` で、譲った時間が分かる。

### 4.2 手すき生成（[idle_thumb.rs](../../src/view_explorer/idle_thumb.rs)）

新規送信の条件に、「`ForegroundIoGuard` が静か（最後の終了から1.5秒以上）」を足した（`FG_QUIET`）。
**止めるのではなく、読み進めている間だけ送らない。** 手が止まれば自動で再開する。設定（ON/OFF・待ち時間・「ビューアーを開いている間も続ける」）は変えていない。
送信済みの1件は止められない。1.5秒は、ページ送りの間隔より長めにして、ぶつかる確率を下げるための値。

### 4.3 タグパネルの高画質プレビュー（[panels.rs](../../src/view_explorer/panels.rs)）

生成リクエストを、次の3つがそろったときだけ出す（`tag_preview_ready_to_request`）。

1. 同じファイルの選択が 0.4秒続いた（`TAG_PREVIEW_DEBOUNCE`）。ダブルクリックの1回目の選択では始まらない。矢印キーで選択を動かしている間に、通り過ぎる行のプレビューが走ることも減る。
2. アーカイブを開く処理中でない（`pending_open`）。
3. ページ読み等の `ForegroundIoGuard` が、終わってから 0.5秒以上たっている（`TAG_PREVIEW_FG_QUIET`）。

満たさない間は、グリッド用サムネで代用表示する。満たす頃に再描画を予約するので、手を動かさなくても高画質に切り替わる。

### 4.4 サムネバー（アーカイブ内サムネワーカー）

ディスクから読むジョブ（FileCache に載っていないもの）だけ、次の2つを行う。FileCache のメモリから作れるジョブは、どちらも不要。

- **同時に丸読みする数を2本に絞る**（`THUMB_DISK_READ_MAX`、`ReadLimiter`）。HDD では並行しても帯域は増えず、シークが散るだけ。
- **ページ用デコードワーカー・オープン処理が動いている間は、次のジョブを始めずに待つ**（`wait_page_jobs_idle`。終了後の静けさ100ms・待ちの上限3秒）。上限があるので、ページ送りが続いてもサムネバーが出ない状態にはならない。

すでに読み始めた分は止められない。

## 5. 計測ログ（`[perf/open]`）

設定→デバッグの perf ログ（`app_log_perf`）がONのとき、標準エラーに出る。**ログは残す方針**（出力が多いのは `ページ内訳` と `ページジョブ`）。

| 行 | 意味 |
|---|---|
| `一覧 近道(中央ディレクトリ)=…ms` / `一覧 近道は使えず従来経路へ（…ms 消費）` | 一覧取得の近道の成否と時間 |
| `一覧 ZipArchive::new=…ms entries=N` | 従来経路で一覧を作ったときの `ZipArchive::new` の時間 |
| `見積もり 開く=…ms 方式=近道/ZipArchive` | メモリ見積もりの zip の開き方と時間 |
| `見積もり サンプル index=N 展開+見積もり=…ms` | サンプル1枚の読み＋見積もり |
| `ワーカー 名前 entries 一覧 見積もり 詳細 合計` | 開くワーカーの内訳 |
| `クリック→ワーカー結果受信` / `DB記録(メイン)` / `open_viewer(メイン)` | メインスレッド側の受信と後処理 |
| `ページ内訳 名前 ディスク読み サイズ デコード 元=WxH(形式) →WxH 縮小=…ms[経路]` | 1ページぶんの読み・デコード（ページ用とサムネ用の両方）。末尾は静止画の縮小の内訳（元寸法・色形式・縮小先・縮小の所要・縮小に使った経路 `Rgb8:U8x3` `L8:U8` `L8:RGBA→U8x4` `RGBA→U8x4`）。縮小しないときは `縮小なし 変換=…ms`。デコード＝読み後の全処理で、縮小を含む。アニメ・TXTは付かない |
| `ページジョブ(デコードワーカー) index 入力=disk/mem/extracted 所要 元=… →… 縮小=…ms` | ページ用ワーカーの1ジョブ。末尾は上と同じ縮小の内訳 |
| `デコードワーカーがディスクからアーカイブを開く=…ms` | ワーカーが（`FastZip` または `ZipArchive` で）開く時間 |
| `ページ到着 index 表示中 viewer開始から クリックから` | 最初の3件の到着時刻 |
| `FileCache到着 …` / `FileCacheワーカー読み込み=…ms (うち譲り待ち=…ms) サイズ=` | FileCache の丸読み |
| `サムネ(アーカイブ内) index=N ページ読みを優先して待機=…ms` | サムネバーが譲って待った時間（50ms以上のとき） |
| `[perf/thumb] load resize total 対象= edge= 登録サムネ= タグプレビュー=` | エクスプローラー側のサムネ生成（対象ファイル名と種類つき） |

## 6. 実装

- [zip.rs](../../src/fs/archive/zip.rs)：`list_images_zip_fast`・`list_images_zip_slow`・`try_list_images_zip_fast`、`FastZip`、`dos_date_key`。
- [zip_cd.rs](../../src/fs/archive/zip_cd.rs)：`CdEntry` に更新日時（`mod_time`・`mod_date`）を追加。
- [mod.rs](../../src/fs/archive/mod.rs)・[detect.rs](../../src/fs/archive/detect.rs)：拡張子での先行近道、`has_zip_extension`・`remember_zip`、形式キャッシュの `lookup_or`・`remember`。
- [cache.rs](../../src/cache.rs)：`OpenArchive::Fast`、`ForegroundIoGuard`・`foreground_io_quiet_for`・`read_file_yielding`、`PageIoGuard`・`wait_page_jobs_idle`、`ReadLimiter`、ページ内訳・FileCache の計測。
- [open_progress.rs](../../src/view_explorer/open_progress.rs)：ワーカーの計測、2つの印、`OpenTrace`。
- [workers.rs](../../src/view_explorer/workers.rs)：FileCache 到着・ページ到着のログ。
- [idle_thumb.rs](../../src/view_explorer/idle_thumb.rs)・[panels.rs](../../src/view_explorer/panels.rs)：§4.2・§4.3。

テスト（`cargo test`）：
- zip.rs：近道と従来経路の一覧の完全一致（名前・フォルダ・同名衝突・日本語名・日付の端・TXTの既定／分割）、UTF-8 フラグ無しの非 ASCII 名での戻り、`dos_date_key` と zip クレートの一致（範囲外を含む）、`FastZip` の生バイト・表示名の一致、同名・CP437 名で開かないこと、拡張子での先行近道と形式キャッシュ、中身が 7z の `.zip` は zip と覚えないこと。
- cache.rs：`read_file_yielding` が `std::fs::read` と一致すること、静けさ待ち（ジョブ中は待つ・終了後も静けさぶん待つ・待たずに答える版）、ページ優先の待ち（上限で抜ける）、`ReadLimiter`（枠が埋まると待ち、返すと進む）。

## 7. 手動テスト

冷たい状態にしてから測る。全体のキャッシュを落とすには `sync && echo 3 | sudo tee /proc/sys/vm/drop_caches`（特定ファイルだけなら `dd of=<ファイル> oflag=nocache conv=notrunc,fdatasync count=0`）。**測るのは1回だけ**（2回目は温まる）。

| # | 手順 | 期待 |
|---|---|---|
| 1 | キャッシュを落とし、大きい zip（1GB 前後）をダブルクリック | クリック→ワーカー結果が 0.3秒程度以内。`一覧 近道(…)` が出て、`方式=近道` |
| 2 | 同じ本で、2ページ目（アニメ画像が多い本なら特に）へ送る | `ページジョブ index=1` が数十〜100ms 台。1秒を超えない |
| 3 | 本を開いた直後に、別の大きい本を開く | 2冊目の `クリック→ワーカー結果受信` が 0.3〜0.6 秒程度以内 |
| 4 | ビューアーを開いたまま数秒放置 | `FileCache…` が読み込みを完了し、`うち譲り待ち` が出る。サムネバーが全ページ分出る |
| 5 | 1回クリックで選択し、0.4秒待つ | 右タグパネルが、グリッド用サムネ→高画質に切り替わる。ダブルクリックでは、開く処理が先に走る |
| 6 | ビューアーを開いたまま、エクスプローラーを放置 | 手すき生成が止まりっぱなしにならず、静かなときに再開する（`[idle-thumb]` ログ） |
| 7 | ページ送りを連続で行う | サムネバーの待ち（`ページ読みを優先して待機`）が3秒を超えない。送りが止まれば、サムネバーが出揃う |
| 8 | TXT が入った zip（TXT分割ON/OFFの両方）を開く | ページ数・並び順・TXTのページ表示が、従来と同じ |
| 9 | 日本語名（SJIS・UTF-8 の両方）の zip を開く | 一覧・ページが従来と同じ。UTF-8 フラグ無しの非 ASCII 名は `近道は使えず従来経路へ` が出る |
| 10 | 拡張子 `.zip` の 7z を開く | これまでどおり開ける（近道は引き返す） |
| 11 | ローカルヘッダだけ壊れた zip を開く | 一覧は出るが、ページが読めない（§3.3 既知の差）。中央ディレクトリが壊れたものは「無効なアーカイブ」 |
| 12 | 7z / tar を開く | 動作が変わっていないこと（展開は従来どおり。対象外） |

## 8. 見送ったもの

- **GIF/WebP は先頭だけ読む**：サムネバーはフレーム0だけでよいが、deflate の途中打ち切りなど設計が重い。同時2本＋ページ優先で、ページ読みの遅れは解消したので見送り。
- **7z / tar の高速化**：展開が必須で、別の話。tar は未確認。
