# 現フォルダ内タグ情報取得（一括タグ付け）

表示中の実フォルダ直下のアーカイブを背景で調べ、info.txt・ファイル名・拡張子から「付けたいタグ」の候補を作る。
確認ウィンドウ（2枚）で採否を選び、「適用」で、DBバックアップのあと、マスターへの追加とファイルへのタグ付けを一括で行う。

## 入口と対象

- 入口: タグパネルの最上段・左右中央のボタン「現フォルダ内タグ情報取得」。
- 押せるのは、フォルダを表示していて、対象のアーカイブがあるとき。**仮想フォルダも対象**（開いたノードの実パスの直下を走査する。仮想ルート `/` とリンク切れは一覧が空なので押せない）。お気に入り・検索・類似・タグ検索タブでは押せない（ホバーで理由が出る）。
- 対象は、表示中のフォルダ直下のアーカイブ（サブフォルダは含まない）。単体の画像ファイルと、無効アーカイブは除く。
- info.txt の取得は zip/cbz のみ。7z・tar・フォルダも、形式タグの対象にはなる（info.txt は「対象外」）。

## 取得元と候補

| 種類 | 元 | 備考 |
|---|---|---|
| アーカイブ形式 | ファイル名の拡張子（`tar.gz` などの複合拡張子を先に判定。フォルダ本は「フォルダ」） | 見えているファイル名で決める（マジックバイトは見ない）。未知の拡張子（`rar` など）も新規候補 |
| カテゴリ（メインタグ） | info.txt の `Category:` | 表記のまま（Doujinshi / Manga …）。メインは未設定のファイルにだけ付く |
| 言語 | info.txt の `Language:` → info.txt のタイトル行の末尾 `[言語]` → ファイル名の末尾 `[言語]` | 辞書（日本語・英語・中国語・韓国語ほか）に合うものだけ。`[DL版]` などは言語にしない |
| イベント | info.txt のタイトル行の先頭 `(C105)` → ファイル名の先頭 `(C105)` | |
| 作者・グループ | info.txt のタイトル行の先頭 `[グループ(作者)]` → ファイル名の先頭 `[...]` | 下記 |

- 取得元の優先は、**アーカイブ内の info.txt が正**で、ファイル名は無い部分だけを補う。
- `Tags:` 節の解析はしない。

### 作者・グループの判定

- `[A(B)]` は一般系（外=グループ、内=作者）を基本にする。既存の作者・グループのタグとの類似度の合計が高い向きがあれば、その向きに直す。
  どちらにも裏づけが無い向きは「未確定」の印が付く。
- `[X]` 単独は、既存のグループにだけ完全一致するならグループ、それ以外は作者の候補にする。
  既存に類似するタグがあれば、類似度の高い順に提案する（初期は未選択）。どれにも類似しなければ、作者の新規候補（未確定）。

### 照合（完全一致と類似）

- 完全一致: 正規化4項目（全角半角・スペース・ハイフンとアンダーバー・特殊文字）を適用したキーが等しい。大文字小文字は常に同一視。
- 類似: 上記にローマ字の表記ゆれの吸収（5つ目）を足したキーの、編集距離から求めた類似度（0〜100%）。完全一致でなければ99%を超えない。
  - ローマ字: `kouji` / `kohji` / `kōji` / `koji`、`si`/`shi`、`ti`/`chi`、`tu`/`tsu`、`hu`/`fu`、`zi`/`ji`、`sya`/`sha`、`tya`/`cha` などを同一視する。
  - 仮名はローマ字に直して比べる（`コウジ` と `Kouji`）。漢字は読みを推測できないので、そのまま。
  - ひらがなとカタカナは、完全一致ではなく類似（同じ読み）として扱う。
- 初期の採否: 完全一致は採用、類似があるものは未選択（提案を選ぶ）、類似を持たない新規は採用（新規作成）。
- 登録名: UIが日本語なら日本語の表記、それ以外は英字の表記を優先する。「全角半角」がONなら、登録名も正規化する（半角カナ→全角カナ、全角英数→半角）。

## 確認ウィンドウ（2枚）

- 1枚目: 作者・グループ以外（形式・カテゴリ・言語・イベント）。「次へ」。
- 2枚目: 作者・グループ。「戻る」「適用」「キャンセル」。窓1が空なら2枚目から、窓2が空なら1枚目に「適用」が出る。
- 上部の切替: 正規化5項目（全角半角・スペース・ハイフンとアンダーバー・特殊文字・ローマ字ゆれ）と、類似度のしきい値（50〜100%、既定80%）。
  変えると別スレッドで候補を作り直し、手で変えた採否は同じ候補に引き継ぐ。スライダーは離したときに確定。設定は state の `app_tag_match`（`全角半角,スペース,ハイフン,特殊文字,ローマ字,しきい値`）に保存する。
- 一覧: 種類ごとの見出し、類似品の見出し（まとめて採用・まとめて不採用）、各行（採否・名前・件数・未確定・既存への対応・類似提案の選択欄）。
  上部に「すべて採用」「すべて不採用」「未確定を不採用」「未確定のみ表示」。
- 「採用」にすると、初期が既存の完全一致ならそれ、類似提案があれば最上位、無ければ新規作成になる。「付けない」にするとスキップ。

### 新規要素の上限

- 各窓で、新規要素（既存の完全一致でないもの）が **1000個を超えると警告**（続行できる）。
- どちらかの窓で **3000個を超えると、エラー**。ウィンドウを出さず、何も書き込まずに終わる。
  「フォルダに格納されているタグ情報量が多すぎます（対象要素数N個/上限値3000個）。ファイルを減らしたフォルダを対象にして再試行してください」。Nは超えた側の数（両方なら多い方）。
- 定数は `tag_candidates.rs` の `WARN_NEW_ELEMENTS` / `ERROR_NEW_ELEMENTS`。

## 別名でまとめる（`A|B|C`）

類似品を、独立した要素ではなく「別名つきの1要素」にまとめられる。要素名の文字列を縦棒で区切る（`Kouji|Koji|コウジ`）。JSONの形式は変わらない。

### 要素名の規則
- `|` で区切った各部分が別名。先頭が主表記。前後の空白と空の別名は捨てる。
- 候補の名前に `|` そのものが含まれるときは、登録時に全角 `｜` に置換する（エスケープ機構は無い）。既に `|` を含む既存の要素は、そのまま別名として扱う。
- 照合・重複判定は、どれかの別名が一致すれば同じ要素。完全一致は別名のどれかと一致、類似は最も近い別名の類似度。類似提案には、要素の全体名と近かった別名（`≈ 別名`）が出る。
- 以前は `|` を無視する記号として扱っていたが、いまは区切り。`ko|uji` は `kouji` と一致しない。

### 導線
1. **類似提案から**: 各行の選択欄に「別名に追加: 既存要素 ← 名前」がある。選ぶと、既存の要素名が `Kouji` → `Kouji|Koji` に書き換わる（次回から完全一致で自動採用される）。
2. **行をまとめる**: 各行の先頭の「まとめる」チェックを2つ以上入れ、「まとめる（N件）を確定」で1つの候補にする。同じ種類（窓内）のみ。
   類似品の束の見出しにある「束をまとめる」で、束全体を一度にまとめられる。
3. **分解**: まとめた行の「別名…」メニューから「まとめを分解」。元の候補に戻る（元の採否も戻る）。
4. **先頭にする別名**: 同じ「別名…」メニューのラジオで入れ替える。

### まとめた候補の扱い
- メンバーに既存要素への完全一致が1つあれば、その要素に不足している別名を追加する。無ければ、別名を `|` でつないだ名前で新規要素。
- 異なる既存要素に複数一致するときは拒否する（既存要素どうしの統合は非対応）。別名が他の既存要素の別名と重なるときも拒否し、重なる別名と要素名を示す。
- 採否は、メンバーのどれかが採用なら採用、全部不採用なら不採用。あとから行のチェックで変えられる。
- 照合の切替で候補を作り直しても、まとめは復元される（まとめた候補の表記が重なる候補を集める）。
- 名前の絞り込み欄（各窓）: 別名・見つかった表記を含む部分一致。正規化設定に従う。

### 表示
- チップ（タグパネル・タグ検索・メインタグのドラム）は先頭の別名だけを出し、ホバーで全文。
- タグ管理の要素チップ（フラット表示）は、別名があれば文字部分のクリックで「先頭にする別名」のラジオが開く。tier の編集欄は全文。
- 確認ウィンドウの「→ 既存: …」は全文。

### 適用前の確認
既存要素の名前が書き換わる適用では、「適用」を押すと一覧（`Kouji → Kouji|Koji`）のモーダルが出て、「このまま適用」で進む。
別名が他の要素と重なるため書き換えない候補があれば、その件数も出る（タグだけ付く）。

## 適用

「適用」で次を、別スレッドで順に行う（進捗オーバーレイが出て、背後の操作は止まる）。

1. **DBバックアップ**（既存の世代バックアップ）。失敗したら、何も変更せずに中止（マスターも保存しない）。
2. **マスターの保存**: 無いカテゴリ（作者・グループ・言語・イベント）を作り、新規要素を追加する。カテゴリは複数選択。同じ正規化名（別名のどれかが重なる場合を含む）の要素は重複させない。別名の追加が決まった既存要素は、名前を書き換える。
3. **ファイルへのタグ付け**: ファイルごとに、DBから現在のタグを読み直し、**既存のタグを消さずに**足す。
   - メインは、未設定のファイルにだけ付く。
   - 排他のカテゴリ（メイン・単一選択・アーカイブ形式）は、既存に要素が無いときだけ1つ付く。
   - 変化が無いファイルは書かない。

完了のトーストに、タグが増えたファイル数・変化なし・失敗・新規要素数・新規カテゴリ数・バックアップ世代名が出る。別名を追加した既存要素があれば、その数も出る（別名が重なって追加しなかった候補があれば、その件数も）。
選択中のファイルのタグ表示は、読み直される。

## システムカテゴリ「アーカイブ形式」

- 起動時に無ければ自動作成する（初期要素: zip / cbz / 7z / cb7 / tar / cbt / tar.gz / tgz / tar.zst / tzst / フォルダ）。種別キー `archive_format` でJSONに保存するので、名前を変えても追跡できる。
- 削除できない（タグ管理で「－」が押せない）。名前・色の変更と、要素の追加・削除はできる。要素を全部消しても補充しない。
- 複数選択のカテゴリ（チップ表示）。1ファイル1要素は、自動付与の規則で守る（手動では複数を選べる）。

## 未対応・注意

- info.txt の取得は zip/cbz のみ。
- 適用の途中でのキャンセルはできない。適用後に元へ戻すには、DBのバックアップ世代（設定のバックアップ画面）から復元する。
- 切替の変更は、作り直しのたびに別スレッドで照合する。件数が多いと、反映に少し時間がかかる。
- 走査中に別フォルダへ移ると、結果は捨てられる（走査中は背後の操作を止めている）。
- 確認ウィンドウの見た目（行の並び・幅）は、実機での確認が前提。
- 既存要素どうしの統合、別名の個別削除（要素名を編集欄で直接編集する）、まとめの保存（ウィンドウを閉じると破棄）は非対応。
- 絞り込み欄は、表示のたびに候補のキーを作り直す。数千件で重いときはキャッシュを検討する。

## 自動テスト

- `tag_source.rs`（info.txt・ファイル名・言語辞書・拡張子）、`tag_similarity.rs`（正規化・ローマ字・類似度・束ね・設定文字列）、
  `tag_candidates.rs`（候補生成・向き補正・提案・上限・採否の操作・引き継ぎ）、`tag_master.rs`（API・別名の分割/結合/検索・システムカテゴリ・タグ合成）、
  `tag_apply.rs`（計画・書き込み・バックアップ失敗時の中止・別名の追加と重なり）、`view_explorer/tag_scan.rs`（走査・キャンセル・既存タグ読み出し）、
  `view_explorer/tag_confirm.rs`（行の組み立て・絞り込み）、`gui_config.rs`（`app_tag_match`）、`tag_manager.rs`（JSON互換）。
- 目視用: `NEKO_SCAN_DIR=<dir> cargo test dump_candidates_for_dir -- --ignored --nocapture` で、フォルダの候補一覧を表示する。

## 手動テスト手順

テスト素材は `test/tag_fixtures/`（14ファイル。gitignore済み。生成スクリプトは手元で再作成可）。隔離した設定（`XDG_CONFIG_HOME` / `XDG_DATA_HOME`）で試すと、本番のDBに触れない。

### 走査と確認ウィンドウ
1. タグパネルを開く。最上段の中央に「現フォルダ内タグ情報取得」が出る。
2. お気に入り・検索・類似・タグ検索タブを表示している間は押せず、ホバーで理由が出る。仮想フォルダ（実パスのあるノード）では押せて、そのノードの実パス直下が走査される。仮想ルート `/` では押せない。
3. `test/tag_fixtures` で押す。進捗が出て、完了トーストに件数が出る。1枚目の確認ウィンドウが開く。
4. 1枚目に、形式（zip・cbz・tar.gz・7z）、カテゴリ（Doujinshi・Manga・Artist CG）、言語（日本語・英語・中国語）、イベント（C105・C104）が並ぶ。形式は既存の要素に対応している。
5. 「次へ」で2枚目。`Hawk Bit`（グループ）・`Kouji`（作者）が、類似品の束としてまとまる。`Koji` / `Kohji` / `こうじ` / `ｺｳｼﾞ` は未選択で、選択欄に `Kouji (99%)` が出る。
6. `Circle A` などは「未確定」の印が付き、新規で採用済み。「未確定を不採用」「未確定のみ表示」が効く。
7. 正規化の5項目としきい値を変えると、束と提案が変わる（しきい値100で類似提案が消える）。手で変えた採否が残る。再起動しても切替の設定が残る。
8. 「キャンセル」で閉じ、何も書き込まれない。走査中のキャンセルも効く。
9. 新規要素が3000個を超えるフォルダ（または、しきい値を下げる確認用に定数を変えたビルド）で、エラーのトーストが出て、ウィンドウが出ない。1000個超で警告の表示が出る。

### 適用
10. 2枚目の「適用」で、進捗オーバーレイが出て、完了トーストが出る（件数・新規要素数・バックアップ世代名）。
11. タグ管理に、新規カテゴリ（作者・グループ・言語・イベント）と新規要素が増えている。メインカテゴリに Doujinshi などが増えている。
12. 各ファイルを選ぶと、タグパネルに付いたタグが出る（形式・メイン・言語・イベント・作者・グループ）。
13. 既に手で付けていたタグは、消えていない。既にメインが設定されていたファイルのメインは、変わっていない。
14. もう一度、取得 → 適用すると、変化なし（タグが増えたファイル数が0）。
15. バックアップ画面に、適用直前の世代が増えている。その世代から復元すると、適用前に戻る。
16. 「付けない」に変えた候補は、適用してもマスターにも作られず、付かない。類似提案を選んだ候補は、既存の要素に付く（新規要素は作られない）。
17. 日本語・英語・中国語で、ボタン・ウィンドウ・トーストの文言が切り替わる。

### 別名でまとめる
18. 作者の窓で、`Kouji`（既存）と `Koji` の「まとめる」にチェック → 「まとめる（2件）を確定」。1行 `Kouji|Koji` になり、「→ 別名に追加: Kouji ← …」が出る。適用前に書き換えの一覧（`Kouji → Kouji|Koji`）が出て、「このまま適用」で進む。
19. 適用後、タグ管理の `Kouji` の要素が `Kouji|Koji` になっている。チップは `Kouji` だけ表示され、ホバーで全文が出る。もう一度、取得 → 適用で、`Koji` は完全一致で自動採用される。
20. 既存要素に一致しない行どうし（例: `Hawk Bit` と `Hawk-Bit` 以外の2グループ）をまとめて適用すると、`A|B` の新規要素が1つできる。両方のファイルにタグが付く。
21. 異なる既存要素（例: `Kouji` と別の既存作者）に当たる行をまとめようとすると、拒否の文言が赤字で出る。種類が違う行（作者とグループ）、1件だけも拒否される。
22. 類似品の束の見出し「束をまとめる」で、束全体が1行になる。「別名…」→「まとめを分解」で元に戻り、元の採否も戻る。
23. 「別名…」のラジオで先頭を入れ替えると、行の名前が `B|A` の並びになり、新規作成ならその並びで登録される。
24. まとめたあとで正規化・しきい値を切り替えても、まとめた行が残る（再生成後の復元）。
25. 絞り込み欄に `kou` / 全角の `ＫＯＵ` / 別名の一部を入れると、該当する行だけに絞られる。✕で解除。
26. タグ管理の要素チップ（別名つき）をクリックすると、「先頭にする別名」のラジオが開く。選ぶと並びが変わり、タグパネル・メインのドラムの表示も先頭の別名に変わる。付与済みのタグは変わらない。
27. 日本語・英語・中国語で、まとめる関連の文言が切り替わる。

## info.txt の見出し確定と、2行タイトルの対応づけ（タグ大ルール計画の単位T）

- **見出し（タイトル群）の確定**: 最初の空でない行（キー行・`<...>` プレースホルダ・URL行以外）から始まり、空行・キー行・プレースホルダ・URL行の手前まで続く連続行（最大4行）。全行を走査して確定する（`tag_source::parse_info_txt`）
- **内部照合に使う行（`InfoTxt.title`）**: かなを含む行、無ければ漢字を含む行、無ければ先頭行。それ以外の行は `InfoTxt.alt_titles` に残す
- **対にして別名で登録**: `alt_titles` のうち、括弧の構造が同じ行（イベントの有無、作者が単独か外側・内側か）があれば、同じ位置の名前を対にする。構造が違う行は対にしない
  - 例: `[えびぞり団 (しえん)]` ⇄ `[Ebizoridan (Shien)]` → グループ `えびぞり団|Ebizoridan`、作者 `しえん|Shien`
  - 同じ表記（`C105` など）は別名にしない。照合は、登録名と対にした表記の両方で行う
  - 主表記は、UIの言語に合わせる（日本語UIなら日本語、それ以外は英語）。登録表記の固定設定は今後の単位で追加する
  - 既存の要素が、片方の表記だけを持っているときは、足りない表記を別名として足す候補（`別名を足す`）になり、初期は採用。確認ウィンドウの「書き換わる既存要素の一覧」の確認を通る。すべての表記を別名に持っていれば、そのまま既存に付ける
  - 確認ウィンドウの候補行に、対にした表記を弱い文字で `（Ebizoridan）` のように表示する
  - 手動で「まとめる」と、対にした別名は引き継がない
- 学習モデルを使う経路でも、同じ位置の名前を対にする（トークンの構造が同じ見出し行がある場合）

### 手動テストの追加（T）
1. 2行タイトルのinfo.txt（英語行・日本語行）があるzipを含むフォルダで取得 → 窓2のグループ・作者に、日本語の名前の横に `（Ebizoridan）` のように英語の表記が出る
2. マスタに英語の表記だけのタグがある状態で取得 → 「別名を足す」候補が初期採用で出る。適用前に「書き換わる既存要素」の一覧に、`Ebizoridan` → `Ebizoridan|えびぞり団` が出る
3. 括弧の構造が違う2行（英語行は作者が単独）では、対にならない
4. 1行だけのinfo.txt・info.txtが無いファイルは、従来と同じ結果になる
