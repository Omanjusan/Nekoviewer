# 選択した項目を維持したままファイラーで開く

アプリは読み取り専用のため、ファイルの削除・整理はOS標準のファイラーで行う。その入口として、
アプリで選択中のファイルを、ファイラー側でも選択した状態にして親フォルダを開く。
削除専用ではなく「アプリの選択状態をファイラーで再現する」汎用機能（重複チェックなどの土台にする）。

実処理は [src/fs/reveal.rs](../../src/fs/reveal.rs)、メニュー/ダイアログは
[src/view_explorer/reveal_ui.rs](../../src/view_explorer/reveal_ui.rs)。

## 操作

ファイルカードを右クリック →「選択した項目を維持したままファイラーで開く」。

- 単品選択: ダイアログなしで、右クリックしたカードのファイルを開く
- 複数選択中: ダイアログでラジオを選ぶ（初期値は上）
  - 複数選択した項目を開く（n件）
  - ホバーした単体のファイルを開く
- ネットワークパス上のファイルはリストから除いて実行する。除外対象があるとき、項目の下に黄字
  「ネットワーク項目は除外されます」を出す。除いた結果が空なら項目はグレー
- 選択が10フォルダを超える親にまたがるとき（検索・お気に入りタブ）は項目をグレーにし、下に赤字
  「10フォルダを超えています」を出す。複数選択中はホバー単体の選択肢もこの場合は使えない
- 親フォルダごとにファイラーを1つ開く（同一フォルダのファイルは1回の呼び出しにまとめる）

## OS別の実装

| OS | 方法 |
|---|---|
| Windows | `SHOpenFolderAndSelectItems`（COM）。`windows-sys` 0.52 に必要な feature が無いため、shell32 の4関数を自前で `extern` 宣言 |
| Linux | `org.freedesktop.FileManager1.ShowItems`（`gdbus`、無ければ `dbus-send`）。URI は `,` `'` 空白・日本語を%エンコード |

## フォールバックと通知

選択が実際に反映されたかはアプリからは検知できない（依頼できたかどうかまで）。

- 選択を依頼できなかった親フォルダ（コマンド無し・非ゼロ終了・COM失敗）は、`open_in_file_manager`
  で親フォルダだけ開き、トースト「選択状態にできなかったため、親フォルダのみ展開」を出す
- 親フォルダが存在しないものは開けず、トースト「開けないフォルダがあった」を出す
- 成功時は何も出さない

### Nautilus の制限（Linux）

Nautilus は `ShowItems` も `nautilus --select` も「1ファイルにつき1ウィンドウ」を開き、同一フォルダの
複数選択を1ウィンドウで再現できない（実測: Nautilus 46.4。3ファイルで3ウィンドウ）。
ウィンドウの乱立を避けるため、`FileManager1` の D-Bus 所有プロセスが `nautilus` のときは、
同一フォルダに2ファイル以上あるフォルダは親フォルダだけ開く（上のフォールバック）。
単一ファイルのフォルダは通常どおり選択付きで開く。

Nautilus 以外のファイラーは未検証で、全ファイルをそのまま渡す（挙動はファイラー次第、成り行き任せ）。

## 試験項目

- Linux(Nautilus): 単一ファイルで選択付きで開く／同一フォルダ複数で親フォルダのみ＋トースト／
  別フォルダにまたがる複数選択で、単一ファイルのフォルダは選択付き
- Linux(Nautilus以外): 同一フォルダ複数が1ウィンドウで全選択になるか
- Windows: 同一フォルダ複数が1ウィンドウで全選択になるか／複数フォルダで親ごとにウィンドウが開くか／
  `,` や空白・日本語を含むパス
- 検索/お気に入りタブで10フォルダ超→グレー＋赤字、ネットワークパス混在→黄字＋除外して実行
- 複数選択中のダイアログ: 「ホバー単体」がネットワークパスのときラジオが無効になる
